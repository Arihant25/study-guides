Two words used everywhere

A tensor here just means a box of numbers with more than two directions. A colour image is a tensor of shape \(H\times W\times C\). Here \(H\) is the height in pixels, \(W\) the width in pixels, and \(C = 3\) is the number of colour channels (red, green, blue). A grey image has \(C = 1\).

A parameter (or weight) is a number the network learns by gradient descent. Counting parameters tells you how much memory a model needs and how much data it needs to avoid overfitting.

4.1Convolution, from signals to images

Lecture L20 · Read: cs231n notes on convolutional networks (the source of several slides)

A convolution slides a small set of weights along the input and, at each position, multiplies and adds. A CNN learns those weights.

An MLP connects every input number to every neuron. For a \(200\times200\) colour image that is \(120{,}000\) inputs, and a layer of the same size needs \(120{,}000\times120{,}000\) weights. That is far too many to learn. A convolution uses two facts about images. A pattern such as an edge is small, so a neuron only needs to look at a small patch. And the same pattern can appear anywhere, so the same weights can be reused at every position. Part 4.4 counts how much this saves.

The 1-D convolution from signal processing

Write the input signal as \(x[n]\), a list of numbers indexed by whole numbers \(n\). Write the filter (also called the kernel) as \(h[n]\). Their convolution is a new signal \(y[n]\), written \(y = x * h\) (the star means convolution, not multiplication).

\[ y[n] = (x*h)[n] = \sum_{m=-\infty}^{\infty} x[m]\,h[n-m] \]
Reading the formula

\(\Sigma\) (capital sigma) means "add up". Here \(m\) runs over every whole number, but only the \(m\) where both \(x[m]\) and \(h[n-m]\) are non-zero add anything, so the sum is always finite in practice.

\(h[n-m]\) as a function of \(m\) is the filter flipped (because of the minus sign in front of \(m\)) and then shifted to position \(n\). So each output value is "flip the filter, slide it to \(n\), multiply with the signal underneath, add". This is what the L20 slide on the convolution integral says in words.

Example. Take \(x = [1, 2, 3]\) at \(n = 0, 1, 2\) and \(h = [1, 1]\) at \(n = 0, 1\).

  • \(y[0] = x[0]h[0] = 1\cdot1 = 1\).
  • \(y[1] \)\({}= x[0]h[1] + x[1]h[0] \)\({}= 1 + 2 \)\({}= 3\).
  • \(y[2] \)\({}= x[1]h[1] + x[2]h[0] \)\({}= 2 + 3 \)\({}= 5\).
  • \(y[3] = x[2]h[1] = 3\).

So \(y = [1, 3, 5, 3]\). The filter \([1,1]\) adds each value to its neighbour, a simple smoothing.

The next paragraph drops the flip, and that unflipped version (correlation) is what a CNN layer computes.

Matched filter, and why CNNs actually use correlation

If you want to find where a known pattern occurs in a long signal, slide the pattern along the signal and compute the dot product (multiply matching entries and add) at each position. Where the signal looks like the pattern, the dot product is large. This is called a matched filter, and the output has a peak where the pattern is. With the convolution formula you get this by convolving with the pattern written backwards, because the formula flips the filter again.

Sliding without flipping is called correlation.

\[ y[n] = \sum_{m} x[n+m]\,h[m] \]
Reading the formula

Here \(m\) runs over the positions of the filter, \(m = 0, 1, \dots, k-1\) for a filter of width \(k\). Output \(n\) multiplies the filter with the \(k\) inputs that start at position \(n\) and adds the products. The filter is not flipped, so \(h[0]\) always meets the leftmost input under it.

Example. Take \(x = [1, 2, 3, 4]\) and \(h = [1, 0, -1]\). Then \(y[0] \)\({}= 1\cdot1 + 2\cdot0 + 3\cdot(-1) \)\({}= -2\) and \(y[1] \)\({}= 2\cdot1 + 3\cdot0 + 4\cdot(-1) \)\({}= -2\). This filter measures how fast the signal is falling, and the signal rises by 1 per step, so both outputs are \(-2\).

Every convolution on the rest of this page is this formula, extended to 2-D in 4.2. The output-size box in 4.3 counts how many positions \(n\) there are.

Deep learning libraries compute correlation and still call it convolution. It makes no difference to learning. The weights are learned, so if the flipped version is better, gradient descent simply learns the flipped weights. From now on "convolution" means this sliding dot product with no flip, as on the slides.

The slide shows three words you will use constantly.

  • Padding adds extra values (usually zeros) at the ends of the input. Without it, a filter of width 3 on 8 inputs fits in only 6 positions, and the output shrinks. With one zero at each end it fits in 8 positions.
  • Weight sharing means the same 3 weights are used at every position. That is why the layer has 3 parameters however long the input is.
  • Each output depends only on 3 neighbouring inputs. This is called local connectivity.

Several filters and several channels

One filter detects one kind of pattern. To detect several, use several filters, each with its own weights. Each filter gives its own output row, called a channel or feature map. The next layer then sees an input with several channels, and each of its filters must have one set of weights per input channel, added together.

\[ \text{weights} = (\text{filter width}) \times C_{\text{in}} \times C_{\text{out}} \]

This is the 1-D version of the formula in 4.4. It ignores the bias, one extra number per output channel, as the slide does.

Remember
  • Convolution formula \(y[n] = \sum_m x[m]h[n-m]\) flips the filter. CNNs use the unflipped sliding dot product (correlation) and call it convolution.
  • A large output means "the input here looks like the filter". This is the matched-filter idea.
  • Padding keeps the output length. Weight sharing makes the parameter count independent of the input size.

4.2The convolutional layer and the whole CNN

Lecture L20 and the recap in L21 · Read: cs231n, "ConvNet layers"

In 2-D the filter is a small square of weights that slides over the image. Stacks of convolution, ReLU and pooling turn an image into a small set of feature maps, which an MLP then classifies.

2-D convolution

For an image \(x[i, j]\) (row \(i\), column \(j\)) and a \(k\times k\) filter \(h\), the output at position \((m, n)\) is the dot product of the filter with the \(k\times k\) patch whose top-left corner is at \((m, n)\).

\[ y[m, n] = \sum_{a}\sum_{b} x[m+a,\, n+b]\, h[a, b] \]

Here \(a\) and \(b\) each run from 0 to \(k - 1\).

Reading the formula

The two sums run over the rows \(a\) and columns \(b\) of the filter. So the output is "multiply each filter weight with the pixel under it, then add all \(k^2\) products".

The slide writes the flipped version, \(\sum_j\sum_i x[i,j]\,h[m-i,n-j]\), as in signal processing. As in 4.1, CNNs use the version above.

Example. The patch \(\begin{bmatrix}1&0\\0&1\end{bmatrix}\) and the filter \(\begin{bmatrix}1&-1\\-1&1\end{bmatrix}\) give \(1\cdot1 + 0\cdot(-1) + 0\cdot(-1) + 1\cdot1 \)\({}= 2\).

The \(6\times6\) image question at the end of this section uses this formula at each position, and 4.3 counts the positions.

Filter 1 is a diagonal-line detector. A patch with 1s exactly on the diagonal and 0s elsewhere scores \(1+1+1 = 3\). Any 1 off the diagonal subtracts 1. The two places marked 3 on the slide are the two diagonal strokes in the image. This is the matched-filter idea in 2-D.

Stride

The stride \(s\) is how far the filter moves between positions. With \(s = 1\) it visits every position. With \(s = 2\) it skips every other one, so the output is about half the size in each direction. L20 slide 15 shows Filter 1 with stride 2 on the same image, giving a \(2\times2\) output.

Pooling

Max pooling slides a window over a feature map and keeps only the largest value in each window. It has no parameters. It shrinks the map, and it makes the output change less when the pattern moves by a pixel, because the maximum of a window does not care where in the window the peak is.

Channels in 2-D

A colour image has 3 channels, so a "\(3\times3\)" filter on it is really \(3\times3\times3\), made of a \(3\times3\) square for each of the red, green and blue channels. The 27 products are all added into one number. So one filter turns an \(H\times W\times C_{\text{in}}\) input into a single \(H'\times W'\) map, and \(C_{\text{out}}\) filters give an \(H'\times W'\times C_{\text{out}}\) output. The number of output channels is the number of filters.

The whole CNN

  1. Convolution, then a non-linearity such as ReLU (\(\max(0, z)\), from the neural networks page), then pooling. Repeat this block several times. Each time the maps get smaller and the number of channels usually grows.
  2. Flatten the last set of maps, which means writing all its numbers in one long vector.
  3. Feed that vector to fully connected (MLP) layers, ending in a softmax over the classes (cat, dog, and so on). A softmax turns a list of scores into probabilities that are positive and add up to 1, and 4.8 gives its formula.

The convolution part is often called the backbone or feature extractor, and the MLP at the end is the head. The whole thing is trained end to end with backpropagation. The gradient of a convolution with respect to a filter weight is the sum, over all positions, of the input pixel that weight touched times the gradient arriving at that output, because the same weight was used at every position.

Remember
  • A 2-D filter spans all input channels, so a \(k\times k\) filter on \(C_{\text{in}}\) channels has \(k\cdot k\cdot C_{\text{in}}\) weights plus one bias.
  • Number of output channels = number of filters.
  • Stride skips positions and shrinks the output. Pooling keeps the maximum of each window and has no parameters.
  • CNN = (conv, ReLU, pool) repeated, then flatten, then fully connected layers and softmax.

4.3The output size of a convolution

Lecture L20, slides 18, 19 and 26

With input width \(n\), filter width \(k\), padding \(p\) and stride \(s\), the output width is \(\lfloor (n + 2p - k)/s \rfloor + 1\).

Every shape question in a CNN comes down to this one formula, applied to the height and the width separately. Pooling layers use the same formula, with the pooling window as \(k\).

\[ n_{\text{out}} = \left\lfloor \frac{n + 2p - k}{s} \right\rfloor + 1 \]
Reading the formula

\(n\) is the input width, \(k\) the filter width, \(p\) the number of zeros added on each side (so \(2p\) in total) and \(s\) the stride. The brackets \(\lfloor\ \rfloor\) mean "round down to a whole number" (the floor).

The top, \(n + 2p - k\), is how far the filter's left edge can travel. The division by \(s\) counts how many steps of size \(s\) fit in that distance. The \(+1\) counts the starting position, which is not a step.

Example. A \(32\times32\) image with a \(5\times5\) filter, \(p = 2\) and \(s = 1\) gives \((32 + 4 - 5)/1 + 1 = 32\). The size is kept. With \(p = 0\) instead it gives \((32 - 5)/1 + 1 = 28\).

The slide writes the same formula as \(W_2 = (W_1 - F + 2P)/S + 1\), with \(F\) for the filter size.

The box below derives it. Pooling layers (4.2), AlexNet (4.4) and the ViT patch count (4.13) all use it.

Write this in the exam

Show that a filter of width \(k\) with stride \(s\) on an input of width \(n\) with padding \(p\) gives \(\lfloor (n+2p-k)/s \rfloor + 1\) outputs.

  1. After padding, the input has width \(n + 2p\).
  2. Number the positions from 0. The filter starts at \(0, s, 2s, \dots\), and a start \(t\) is allowed when \(t + k \le n + 2p\).
    Why (3 steps)
    1. The filter covers positions \(t, t+1, \dots, t+k-1\) when it starts at \(t\).
    2. The last padded position is \(n + 2p - 1\), so the filter fits when \(t + k - 1 \le n + 2p - 1\).
    3. Add 1 to both sides. \(t + k \le n + 2p\).
  3. So the allowed starts are \(t = js\) with \(0 \le js \le n + 2p - k\), that is \(0 \le j \le (n+2p-k)/s\).
  4. \(j\) is a whole number, so \(j \)\({}= 0, 1, \dots, \lfloor (n+2p-k)/s\rfloor\). Counting these gives \(\lfloor (n+2p-k)/s \rfloor + 1\) outputs.
    Why (covers lines 3 and 4, 4 steps)
    1. The \(j\)-th start is \(t = js\), for \(j = 0, 1, 2, \dots\).
    2. Substitute into line 2. \(js + k \le n + 2p\), so \(js \le n + 2p - k\).
    3. Divide both sides by \(s\) (which is positive). \(j \le (n + 2p - k)/s\).
    4. The whole numbers from 0 up to \(\lfloor (n+2p-k)/s \rfloor\) are that number plus 1 in count, because the list starts at 0.
  5. With \(s = 1\), the output width equals \(n\) when \(p = (k-1)/2\). This is "same" padding.
    Why (3 steps)
    1. Put \(s = 1\) into line 4. Dividing by 1 changes nothing and the top is a whole number, so \(n_{\text{out}} \)\({}= n + 2p - k + 1\).
    2. Ask for \(n_{\text{out}} = n\). That is \(n + 2p - k + 1 = n\).
    3. Subtract \(n\) from both sides, so \(2p = k - 1\). Divide by 2. \(p = (k-1)/2\).

Two consequences are used all the time.

  • "Same" padding. By line 5 of the box, \(p = (k-1)/2\). So a \(3\times3\) filter uses \(p = 1\) and a \(5\times5\) filter uses \(p = 2\). L20 slide 18 shows the \(3\times3\), \(p = 1\) case.
  • Stride shrinks. With \(s = 2\) the output is roughly half the input, as L20 slide 19 says.
Common mistake

Using \(p\) instead of \(2p\). Padding is added on both sides. Also, if \((n + 2p - k)/s\) is not a whole number, the last few input columns are simply never covered. Some exam questions pick numbers so that it divides exactly, and that is a useful check on your arithmetic.

Remember
  • \(n_{\text{out}} \)\({}= \lfloor (n + 2p - k)/s\rfloor + 1\), for height and width separately. The number of output channels is the number of filters.
  • Same size with stride 1 needs \(p = (k-1)/2\).

4.4Counting parameters

Lecture L20, slides 26 and 27, and L21, slides 13 and 14

A convolutional layer with \(K\) filters of size \(F\times F\) on \(D\) input channels has \((F\cdot F\cdot D + 1)\cdot K\) parameters. A fully connected layer from \(a\) inputs to \(b\) outputs has \(a\cdot b + b\).

Write this in the exam

Count the parameters of a conv layer with \(K\) filters of size \(F\times F\) on an input with \(D\) channels.

  1. Each filter spans all \(D\) input channels, so it has \(F\cdot F\cdot D\) weights.
  2. Each filter has one bias, so it has \(F\cdot F\cdot D + 1\) parameters.
  3. The same filter is used at every position of the output map, so the size of the image adds no parameters.
  4. There are \(K\) filters, so the layer has \((F\cdot F\cdot D + 1)\cdot K\) parameters.
    Why (covers lines 1 to 4, 4 steps)
    1. One output value is the dot product of the filter with an \(F\times F\) patch in each of the \(D\) channels, so it uses \(F\cdot F\cdot D\) weights.
    2. A bias \(b\) is added to the dot product, as in a single neuron \(w\T x + b\). That is one more number per filter.
    3. The same filter and bias are used at every position of the output map. So the map adds no further parameters, however large it is.
    4. Each of the \(K\) filters has its own weights and bias, so multiply by \(K\).

For a fully connected layer every input connects to every output, so it has \(a\cdot b\) weights and \(b\) biases. Fully connected layers are where most of the parameters of a classic CNN live, as AlexNet shows.

4.5Small filters, 1×1 convolutions and inception

Lecture L20, slides 28 to 37, repeated in L21

After AlexNet, networks got deeper by using many small filters, and cheaper by squeezing the channels with \(1\times1\) convolutions before the expensive layers.

Two 3×3 layers instead of one 5×5

The receptive field of a neuron is the patch of the original input that can affect it. A neuron after one \(5\times5\) convolution sees a \(5\times5\) patch. A neuron after two stacked \(3\times3\) convolutions sees the same \(5\times5\) patch, as the slide's figure shows.

Write this in the exam

Compare one \(5\times5\) conv layer with two stacked \(3\times3\) layers, all with \(C\) input and \(C\) output channels.

  1. Receptive field of two \(3\times3\) layers is \(3 + (3 - 1) = 5\), the same as one \(5\times5\).
    Why (3 steps)
    1. A neuron in the second layer sees 3 neighbouring positions of the first layer's output in each direction.
    2. Neighbouring first-layer neurons look at windows that start one position apart, and each window is 3 wide.
    3. So 3 windows starting at positions 0, 1 and 2 cover positions 0 to 4, which is 5 positions. The same holds in the other direction, giving \(5\times5\).
  2. Weights of one \(5\times5\) layer: \(5\cdot5\cdot C\cdot C = 25C^2\).
  3. Weights of two \(3\times3\) layers: \(2\cdot(3\cdot3\cdot C\cdot C) \)\({}= 18C^2\), which is 28 percent fewer.
  4. Two layers also apply two ReLUs instead of one, so the function is more non-linear.

This is the slide's design guideline "5×5C > 2×3×3C" and its reasons. Two small layers need fewer parameters (so they are faster), they have the same receptive field, and they add more non-linearities. VGGNet (2014) used only \(3\times3\) filters for this reason. Three stacked \(3\times3\) layers reach a \(7\times7\) receptive field with \(27C^2\) weights instead of \(49C^2\).

1×1 convolutions

A \(1\times1\) filter looks at a single pixel position, but across all \(D\) input channels. So it computes, at every pixel, a weighted sum of that pixel's \(D\) channel values. With \(K\) such filters it turns \(D\) channels into \(K\) channels without changing the height or width. It is a small fully connected layer applied to each pixel separately, with the same weights at every pixel.

  • With \(K \lt D\) it reduces the number of channels (dimensionality reduction across channels).
  • Followed by a ReLU, it adds a non-linearity without changing the receptive field.

The bottleneck, with numbers

Count multiplications as (number of output values) times (multiplications per output value). One output value of a \(k\times k\) filter on \(D\) channels needs \(k\cdot k\cdot D\) multiplications.

  • Direct. A \(5\times5\) layer from \(28\times28\times192\) to \(28\times28\times32\) needs \((28\cdot28\cdot32)\times(5\cdot5\cdot192) \)\({}= 25{,}088\times4800 \)\({}\approx 120.4\) million.
  • With a bottleneck. First a \(1\times1\) layer to 16 channels needs \((28\cdot28\cdot16)\times192 \)\({}\approx 2.4\) million. Then the \(5\times5\) layer from 16 channels needs \((28\cdot28\cdot32)\times(5\cdot5\cdot16) \)\({}\approx 10.0\) million. Total about 12.4 million.

The narrow 16-channel layer in the middle is called a bottleneck, because the data is squeezed through it like liquid through the neck of a bottle.

The inception module

Which filter size is best for a layer is not known in advance. The inception module (GoogLeNet, 2015) uses \(1\times1\), \(3\times3\) and \(5\times5\) convolutions and a \(3\times3\) max pool in parallel on the same input, with "same" padding so all four outputs have the same height and width. Their outputs are then concatenated along the channel direction. Running all of them directly would be very expensive (slide 33), so each \(3\times3\) and \(5\times5\) branch is preceded by a \(1\times1\) bottleneck, and the pooling branch is followed by one.

Remember
  • Two \(3\times3\) layers have receptive field 5, \(18C^2\) weights and two ReLUs. One \(5\times5\) layer has \(25C^2\) weights and one ReLU.
  • A \(1\times1\) conv mixes channels at each pixel. It changes the channel count and adds non-linearity, and leaves the receptive field alone.
  • Multiplications of a conv layer = (output height · width · channels) × (\(k\cdot k\cdot D\)).
  • Inception = parallel branches of different filter sizes with \(1\times1\) bottlenecks, concatenated.

4.6ResNet and skip connections

Lecture L21, slides 15 to 20

A residual block outputs \(x + F(x)\). The block only has to learn the change \(F\), and the gradient always has a direct path back through the "+ x".

Deeper plain networks train worse

If a deep network were overfitting, its training error would be low and its test error high. Here the deeper network is worse on the training data itself. This is called the degradation problem. It shows that gradient descent fails to find good weights for the deeper network, even though good weights exist.

Good weights do exist, by this argument from the slides. Take the trained 20-layer network and add 36 layers that each compute the identity, \(y = x\). The result is a 56-layer network with exactly the same training error. So the best 56-layer network is at least as good as the 20-layer one. Plain layers simply find it hard to learn the identity, because that needs a precise set of weights.

The fix is to learn the residual

Let \(H(x)\) be the function a block should compute. A residual block instead computes

\[ y = x + F(x), \qquad F(x) = H(x) - x \]

where \(F\) is two weight layers with a ReLU between them, and the "+ x" is the skip connection (or shortcut). \(F\) is called the residual, because it is what is left over after the input.

  • If the identity is the best thing for the block to do, it only has to set its weights to zero, so \(F(x) = 0\). Driving weights to zero is easy for gradient descent, especially with weight decay.
  • If the best function is close to the identity, the block only has to learn a small correction.
Write this in the exam

Show why a skip connection helps the gradient reach early layers.

  1. The block computes \(y = x + F(x)\). By the chain rule, \(\frac{\partial L}{\partial x} \)\({}= \frac{\partial L}{\partial y}\,\frac{\partial y}{\partial x}\).
  2. \(\frac{\partial y}{\partial x} \)\({}= 1 + \frac{\partial F}{\partial x}\), so \(\frac{\partial L}{\partial x} \)\({}= \frac{\partial L}{\partial y}\left(1 + \frac{\partial F}{\partial x}\right)\).
    Why (3 steps)
    1. The derivative of a sum is the sum of the derivatives.
    2. The derivative of \(x\) with respect to \(x\) is 1.
    3. The derivative of \(F(x)\) is \(\frac{\partial F}{\partial x}\). Adding them gives \(1 + \frac{\partial F}{\partial x}\). (For vectors, the 1 becomes the identity matrix.)
  3. So \(\frac{\partial L}{\partial x}\) contains the term \(\frac{\partial L}{\partial y}\) unchanged. Even if \(\frac{\partial F}{\partial x}\) is close to 0, the gradient passes straight through.
  4. In a plain network the same step gives only \(\frac{\partial L}{\partial y}\frac{\partial F}{\partial x}\). A product of many such small factors shrinks towards 0 (vanishing gradient).
    Why (covers lines 3 and 4, 4 steps)
    1. In a plain network, \(y = F(x)\), so \(\frac{\partial y}{\partial x} \)\({}= \frac{\partial F}{\partial x}\) with no 1.
    2. Through \(L\) such layers, backpropagation multiplies \(L\) of these factors.
    3. If each factor is about 0.5, ten layers give \(0.5^{10} \approx 0.001\). The early layers receive almost no gradient and barely learn.
    4. With skips, each factor is \(1 + \frac{\partial F}{\partial x}\). Multiplying out \((1 + a)(1 + b) \)\({}= 1 + a + b + ab\) always keeps a term 1, which is the path along all the skips.

With residual blocks, networks of 50, 101 and 152 layers train well, and deeper ones do better. The skip connection is now in almost every deep network, including the transformer later on this page.

Remember
  • Degradation: a deeper plain network has higher training error. It is an optimisation problem, not overfitting.
  • Residual block \(y = x + F(x)\), with \(F = H - x\). The identity is \(F = 0\), which is easy to learn.
  • \(\partial L/\partial x \)\({}= \partial L/\partial y\,(1 + \partial F/\partial x)\). The 1 carries the gradient directly back.

4.7What CNNs learn, and choosing one

Lecture L21, slides 21 to 35 · Read: Zeiler and Fergus, "Visualizing and Understanding Convolutional Networks" (ECCV 2014), the source of the figures

Early layers learn edges and colours, middle layers learn textures and parts, and late layers learn whole objects. "Deep" means many stages of non-linear feature transformation.

The slide's definition is that a model is deep if it has more than one stage of non-linear feature transformation. Before deep learning, the pipeline was hand-designed features (such as edge histograms) followed by a learned classifier. A CNN learns the whole pipeline from pixels to labels.

The argument on slides 27 to 30 is about variation. Whole faces vary a lot (the same person looks different, different people can look alike), so one filter per face pattern would need far too many filters. Parts such as eyes vary less, and textures and edges vary even less. So it is efficient to detect simple things first and combine them, edges into textures, textures into parts and parts into objects. Each conv layer combines the features of the layer below over a larger receptive field, which is exactly this hierarchy.

Ways to look inside a trained CNN:

  • Show the first layer's filters as small images. They look like oriented edges and colour blobs.
  • For a neuron deeper in, find the image patches that excite it most, or project its activation back to pixel space (Zeiler and Fergus).
  • Watch the filters during training. L21 slide 33 shows that early layers converge (stop changing) faster than later ones.

Which architecture is best? Slides 34 and 35 say it depends on the constraint, not only on accuracy. Compare accuracy, model size (number of parameters), memory, computation (FLOPs, floating point operations) and inference time. Networks around the same accuracy can differ by several times in computation, so a phone app and a server pick different backbones.

Pretraining and fine-tuning. The recap slides of L22 and L23 mention this. A backbone trained on a large dataset such as ImageNet has learned general early and middle features. For a new task with little data, keep those layers (or train them slowly) and train a new head. Section 4.14 returns to this idea for language.

Remember
  • Deep = more than one stage of non-linear feature transformation, learned end to end.
  • Feature hierarchy: edges and colours, then textures, then parts, then objects.
  • Choose an architecture by accuracy and by size, memory, FLOPs and speed together.

4.8Recurrent neural networks

Lecture L22 · Read: Karpathy, "The unreasonable effectiveness of recurrent neural networks" (given on the slides)

An RNN reads a sequence one item at a time and keeps a hidden state \(h_t\) that summarises everything read so far. The same weights are used at every step.

Text, speech and video are sequences, and their length varies. An MLP needs a fixed-size input. A CNN sees only a fixed window. An RNN handles any length by applying the same small network at each time step and passing a memory vector from one step to the next.

\[ h_t = f(U x_t + W h_{t-1}) \]
\[ o_t = \operatorname{softmax}(V h_t) \]
Reading the formula
  • \(x_t\) is the input at time step \(t\) (for example, the one-hot vector of the \(t\)-th character), of length \(d\).
  • \(h_t\) is the hidden state at step \(t\), a vector of length \(h\). It is the network's memory. \(h_0\) is usually all zeros.
  • \(U\) (size \(h\times d\)) maps the input into the hidden space. \(W\) (size \(h\times h\)) maps the previous hidden state. \(V\) (size \(k\times h\)) maps the hidden state to \(k\) output scores.
  • \(f\) is a non-linearity, usually tanh, which squashes each entry into \((-1, 1)\).
  • softmax turns the \(k\) scores into probabilities, \(\operatorname{softmax}(z)_i \)\({}= e^{z_i}/\sum_j e^{z_j}\).

The new memory is a mix of the new input (\(Ux_t\)) and the old memory (\(Wh_{t-1}\)). Because \(h_{t-1}\) depends on \(h_{t-2}\), and so on, \(h_t\) depends on every input so far.

The number of parameters is \(hd + h^2 + kh\) (plus biases), whatever the length of the sequence. This is weight sharing across time, just as a CNN shares weights across space.

Example. With \(d = 3\), \(h = 2\) and \(k = 3\), \(U\) has \(2\cdot3 = 6\) entries, \(W\) has 4 and \(V\) has 6, so 16 weights in all, for a sequence of any length.

The BPTT box below differentiates this equation, and the LSTM in 4.9 replaces it.

Many shapes of input and output

L22 slide 12 lists the ways an RNN can be wired. One to many (an image in, a caption out). Many to one (a sentence in, a sentiment out, using only the last \(o_t\)). Many to many with a delay (translation, where the whole sentence is read before output starts). Many to many in step (a label for every video frame).

Character-level language model

A language model predicts the next item of a sequence from the items before it. At character level, the vocabulary is the set of characters, each input \(x_t\) is a one-hot vector (all zeros with a single 1 marking the character), and \(o_t\) is a probability for every possible next character.

To train on the word "hello" with vocabulary {h, e, l, o}, feed h, e, l, l as inputs and use e, l, l, o as the targets at steps 1 to 4. The loss is the cross-entropy \(-\log o_t[\text{correct character}]\), added over the steps. To generate text afterwards, sample a character from \(o_t\), feed it back in as \(x_{t+1}\), and repeat.

Training: backpropagation through time

Unrolled, an RNN is just a deep network with one layer per time step and tied weights. Backpropagation on the unrolled network is called backpropagation through time (BPTT). The total loss is \(E = \sum_t E_t\), so \(\partial E/\partial W \)\({}= \sum_t \partial E_t/\partial W\).

Write this in the exam

Write \(\partial E_4/\partial W\) for an RNN and explain the vanishing gradient.

  1. \(E_4\) depends on \(W\) through \(h_4\), and \(h_4 = f(Ux_4 + Wh_3)\) depends on \(W\) directly and through \(h_3\), which depends on \(W\) and \(h_2\), and so on.
  2. By the chain rule, \[\frac{\partial E_4}{\partial W} = \sum_{k=1}^{4}\frac{\partial E_4}{\partial \hat o_4}\frac{\partial \hat o_4}{\partial h_4}\frac{\partial h_4}{\partial h_k}\frac{\partial h_k}{\partial W}.\]
    Why (covers lines 1 and 2, 4 steps)
    1. \(W\) appears four times in the unrolled network, once in each of \(h_1, h_2, h_3, h_4\).
    2. Treat the four copies as separate variables. The total derivative is the sum of the derivatives through each copy.
    3. The copy used in \(h_k\) affects \(E_4\) only through \(h_k\), then \(h_{k+1}, \dots, h_4\), then \(\hat o_4\).
    4. Chain those links. \(\frac{\partial h_k}{\partial W}\) here means the direct effect of the copy in step \(k\), holding \(h_{k-1}\) fixed.
  3. Break the middle factor into one-step factors, \(\frac{\partial h_4}{\partial h_k} \)\({}= \prod_{j=k+1}^{4}\frac{\partial h_j}{\partial h_{j-1}}\).
  4. For a scalar RNN with tanh, \(\frac{\partial h_j}{\partial h_{j-1}} \)\({}= w\,(1 - h_j^2)\), whose size is at most \(|w|\).
    Why (3 steps)
    1. \(h_j = \tanh(u x_j + w h_{j-1})\). The derivative of \(\tanh z\) is \(1 - \tanh^2 z\).
    2. Chain rule. Write \(z_j = ux_j + wh_{j-1}\). Then \(\frac{\partial h_j}{\partial h_{j-1}} \)\({}= (1 - \tanh^2 z_j)\cdot w \)\({}= w(1 - h_j^2)\).
    3. \(h_j^2\) lies between 0 and 1, so \(1 - h_j^2\) lies between 0 and 1, and the size is at most \(|w|\).
  5. A term reaching back \(n\) steps contains \(n\) such factors. If they are below 1 the term shrinks like (factor)\(^n\) and vanishes. If they are above 1 it grows and explodes. So early inputs barely affect learning.

For example, \(0.9^{50} \approx 0.005\) and \(1.1^{50} \approx 117\). Exploding gradients are usually handled by gradient clipping (if the gradient's length exceeds a threshold, scale it down to the threshold). Vanishing gradients need a change of architecture, which is the LSTM.

The L22 discussion slide adds two practical points. RNNs are small compared with CNNs, and several can be stacked (the hidden states of one RNN are the inputs of the next). But they cannot be parallelised over time, because step \(t\) needs \(h_{t-1}\) first. Transformers (4.12) remove that limit.

Remember

  • The same \(U, V, W\) at every step, so the parameter count does not depend on the length.
  • BPTT multiplies one Jacobian per step, so gradients vanish or explode over long sequences.

4.9LSTM

Lecture L22, slides 16 to 21 · Read: Olah, "Understanding LSTM networks" (the source of the slide figures)

An LSTM adds a second memory, the cell state \(C_t\), which is updated by adding to it rather than by multiplying. Three gates decide what to forget, what to write and what to read out.

LSTM stands for long short-term memory. The name says that the network's short-term memory (its hidden state) is made to last a long time. The plain RNN overwrites \(h_t\) completely at every step. The LSTM keeps a cell state \(C_t\) that changes slowly, because each step only scales it and adds a little to it (L22 slide 18).

A gate is a vector of numbers between 0 and 1, made with the sigmoid \(\sigma(z) = 1/(1 + e^{-z})\). Multiplying a vector entry by entry with a gate lets through a fraction of each entry: 0 blocks it, 1 passes it whole. The slide calls the gates "soft" because they can be anywhere between 0 and 1, so they are differentiable and can be learned by backpropagation.

Write \([h_{t-1}, x_t]\) for the vector made by stacking \(h_{t-1}\) on top of \(x_t\) (length \(h + d\)), and \(\odot\) for multiplying two vectors entry by entry (the slide writes \(*\)).

\[ f_t = \sigma(W_f[h_{t-1}, x_t] + b_f) \]
\[ i_t = \sigma(W_i[h_{t-1}, x_t] + b_i) \]
\[ \tilde C_t = \tanh(W_C[h_{t-1}, x_t] + b_C) \]
\[ C_t = f_t \odot C_{t-1} + i_t \odot \tilde C_t \]
\[ o_t = \sigma(W_o[h_{t-1}, x_t] + b_o) \]
\[ h_t = o_t \odot \tanh(C_t) \]
Reading the formulas
  • Forget gate \(f_t\): how much of each entry of the old cell \(C_{t-1}\) to keep. 1 keeps it, 0 erases it.
  • Input gate \(i_t\): which entries to update, and how strongly.
  • Candidate \(\tilde C_t\): the new content that could be written, in \((-1, 1)\) because of tanh. The slide calls it the "change contents".
  • Cell update: keep a fraction of the old memory and add a fraction of the new content.
  • Output gate \(o_t\): which parts of the (squashed) cell to expose as the hidden state \(h_t\), which is what the rest of the network sees.

All four of \(f_t, i_t, \tilde C_t, o_t\) are computed from the same input \([h_{t-1}, x_t]\) with four different weight matrices, so they can be computed at the same time (L22 slide 19 says "these 4 matrix computations should be done concurrently"). Each matrix is \(h\times(h + d)\), so an LSTM has \(4(h(h+d) + h)\) parameters, four times a plain RNN layer of the same sizes.

Example. One cell (\(h = 1\)) with \(C_{t-1} = 0.5\). Suppose the four pre-activations come out as 2 (forget), 0 (input), 1 (candidate) and 1 (output).

  1. \(f_t = \sigma(2) \approx 0.881\), \(i_t = \sigma(0) = 0.5\), \(\tilde C_t \)\({}= \tanh(1) \)\({}\approx 0.762\), \(o_t = \sigma(1) \approx 0.731\).
  2. \(C_t \)\({}= 0.881\times0.5 + 0.5\times0.762\)\({}= 0.440 + 0.381 = 0.821\).
  3. \(h_t = 0.731\times\tanh(0.821) \)\({}= 0.731\times0.676 \)\({}\approx 0.494\).

4.10Word embeddings and word2vec

Lecture L23, slides 8 to 10, and L25, slide 31

Each word becomes a dense vector of a few hundred numbers, learned so that words used in similar contexts get similar vectors.

A network needs numbers, not words. The simplest choice is a one-hot vector. With a vocabulary of \(V\) words, word number \(j\) is a vector of length \(V\) with a 1 in place \(j\) and 0 everywhere else. This has two problems. It is very long (\(V\) is tens of thousands), and every pair of different words has dot product 0, so "cat" is exactly as far from "dog" as from "carburettor".

An embedding is a short dense vector (say 300 numbers) for each word, stored as one row of a \(V\times300\) matrix. Multiplying a one-hot vector by this matrix just picks out that word's row, so an embedding layer is a lookup table whose entries are learned.

Word2vec (2013) learns these vectors with a fill-in-the-blank task on raw text. In "the cat sat on the mat", hide "sat" and train a small network to predict it from "cat" and "on" (CBOW, continuous bag of words), or train it to predict "cat" and "on" from "sat" (skip-gram). No human labels are needed, because the text itself supplies the answers. This is an early example of the self-supervised learning in 4.14. Words that appear in similar contexts must produce similar predictions, so they end up with similar vectors.

Similarity between two embeddings is measured by the cosine similarity, the cosine of the angle between them.

\[ \cos(a, b) = \frac{a\T b}{\|a\|\,\|b\|} \]
Reading the formula

The top, \(a\T b\), is the dot product (multiply matching entries and add). The bottom divides by the two lengths, \(\|a\| = \sqrt{a\T a}\), so the answer does not change if a vector is made longer. Only the direction counts.

It is 1 for vectors pointing the same way, 0 for perpendicular ones and −1 for opposite ones.

Example. \(a = (1, 1)\) and \(b = (2, 0)\). \(a\T b = 2\), \(\|a\| = \sqrt2\), \(\|b\| = 2\). So \(\cos = 2/(2\sqrt2) \)\({}= 1/\sqrt2 \approx 0.707\), an angle of 45 degrees.

The analogy question below finds the answer word by the largest cosine, and contrastive learning in 4.15 also measures closeness between embeddings.

Word arithmetic

Trained embeddings show regular offsets. The slide writes king − queen = man − woman. Rearranged, king − man + woman ≈ queen. The vector difference "male to female" is roughly the same for every pair. To answer "man is to king as woman is to ?", compute king − man + woman and find the word whose vector has the highest cosine similarity with it (leaving out the three input words).

Remember
  • A one-hot vector has length \(V\), and all words are equally far apart. An embedding is short, dense and learned, and similar words are close.
  • An embedding layer is a \(V\times d\) matrix. One-hot times the matrix picks a row.
  • Word2vec learns by predicting a word from its context (CBOW) or the context from a word (skip-gram).
  • Analogies: king − man + woman ≈ queen, found by cosine similarity.

4.11Self-attention

Lecture L23, slides 11 to 30, repeated in L24 · Read: Alammar, "The illustrated transformer" (the source of the multi-head slide)

Self-attention replaces each vector in a sequence with a weighted average of all the vectors, where the weights come from how well they match. Every output sees every input in one step.

Look at L23 slide 13: "The animal did not cross the road because it was too tired" and "... because it was too wide." In the first sentence "it" means the animal, in the second the road. To build a good vector for "it", the model must look at other words in the sentence and decide which matter. An RNN can only pass this information step by step through \(h_t\). A convolution only sees a fixed window. Self-attention lets every word look at every other word directly.

Simple self-attention (no learned weights)

Given inputs \(x_1, \dots, x_n\) (each a vector of length \(d\)), output \(i\) is

\[ w'_{ij} = x_i\T x_j \]
\[ w_{ij} = \frac{\exp w'_{ij}}{\sum_{l}\exp w'_{il}} \]
\[ y_i = \sum_j w_{ij}\,x_j \]
Reading the formula
  • \(w'_{ij}\) is a raw score. The dot product is large when \(x_i\) and \(x_j\) point the same way.
  • \(w_{ij}\) is the softmax over \(j\). It makes the weights for output \(i\) positive and adding up to 1.
  • \(y_i\) is a weighted average of all inputs, with most weight on the inputs most similar to \(x_i\).

The slide makes three observations (L23 slide 16). There are as many outputs as inputs, of the same size. Every output depends on every input. And the weights \(w_{ij}\) are not learned parameters. They are computed from the data. This layer has no parameters at all, and it treats the input as a set, since shuffling the inputs just shuffles the outputs. Order must be added separately (positional encoding, 4.12).

Example. \(x_1 = (1, 0)\), \(x_2 = (0, 1)\). The scores for \(i = 1\) are \(x_1\T x_1 = 1\) and \(x_1\T x_2 = 0\). The softmax gives \(e^1/(e^1 + e^0) \)\({}= 2.718/3.718 \)\({}\approx 0.73\) and \(0.27\). So \(y_1 \)\({}= 0.73(1,0) + 0.27(0,1) \)\({}= (0.73, 0.27)\).

The next part gives each role of \(x\) its own learned matrix, which turns this formula into the full attention formula.

Queries, keys and values

In simple self-attention, each input vector plays three roles. To give each role its own learned version, multiply \(x_i\) by three learned matrices.

\[ q_i = W_Q\T x_i,\qquad k_i = W_K\T x_i,\qquad v_i = W_V\T x_i \]

The query \(q_i\) describes what position \(i\) is looking for. The key \(k_j\) describes what position \(j\) offers to be matched against. The value \(v_j\) is what position \(j\) contributes if it is chosen. The names come from looking up a database, where a query is matched against keys and the matching entries' values are returned. Here the match is soft, so every value is returned with some weight.

Stack the inputs as the rows of a matrix \(X\) (size \(n\times d\), one token per row). Then \(Q = XW_Q\), \(K = XW_K\), \(V = XW_V\), and all outputs are computed at once.

\[ \operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{QK\T}{\sqrt{d_k}}\right)V \]
Reading the formula
  • \(QK\T\) is \(n\times n\). Its entry \((i, j)\) is \(q_i\T k_j\), the score of position \(i\) for position \(j\).
  • Dividing by \(\sqrt{d_k}\), the square root of the query and key length, keeps the scores from growing with \(d_k\). The derivation below shows why.
  • The softmax is applied to each row separately, so each row of weights adds up to 1.
  • Multiplying by \(V\) replaces each row by the weighted average of the value vectors.

Counting work, \(QK\T\) has \(n^2\) entries. So attention costs grow with the square of the sequence length. The slide notes that \(n\) is typically about 4096 tokens in current models.

Example. Two tokens with \(Q = K = V = I\) (the \(2\times2\) identity) and \(d_k = 1\). Then \(QK\T = I\). Row 1 is \((1, 0)\), whose softmax is \((e, 1)/(e + 1) \)\({}\approx (0.73, 0.27)\). So output 1 is \(0.73(1, 0) + 0.27(0, 1) \)\({}= (0.73, 0.27)\), the same as the simple example above.

The first practice question below works a 3-token example in full, and every transformer block in 4.12 starts with this formula.

Write this in the exam

Explain why the scores are divided by \(\sqrt{d_k}\).

  1. Assume the entries of \(q\) and \(k\) are independent with mean 0 and variance 1.
  2. Then \(q\T k \)\({}= \sum_{m=1}^{d_k} q_m k_m\) has mean 0 and variance \(d_k\).
    Why (4 steps)
    1. Each term \(q_mk_m\) has mean \(E[q_m]E[k_m] = 0\times0 = 0\), using independence.
    2. Its variance is \(E[q_m^2k_m^2] - 0^2 \)\({}= E[q_m^2]E[k_m^2] \)\({}= 1\times1 \)\({}= 1\).
    3. The \(d_k\) terms are independent, so their variances add. Total variance \(d_k\).
    4. The standard deviation is the square root of the variance, \(\sqrt{d_k}\).
  3. So with \(d_k = 64\) the scores are typically about \(\pm8\). Dividing by \(\sqrt{d_k}\) brings the variance back to 1.
  4. Without the division, large scores make the softmax almost one-hot (one weight near 1, the rest near 0). There its gradient is almost 0, so training stalls.
    Why (3 steps)
    1. Softmax of (8, 0, 0) is \(e^8/(e^8 + 2) \approx 0.9993\) for the first entry and about 0.0003 for the others.
    2. The derivative of a softmax output \(s_i\) with respect to its own score is \(s_i(1 - s_i)\), which here is about \(0.9993\times0.0007 \)\({}\approx 0.0007\).
    3. So changing the scores barely changes the weights, and gradient descent gets almost no signal.

Masked (causal) self-attention

Write the masked scores as

\[ S = \frac{QK\T + M}{\sqrt{d_k}},\qquad M_{ij} = \begin{cases}0 & j \le i\\ -\infty & j \gt i\end{cases} \]

Then the output of masked attention is

\[ \operatorname{softmax}(S)\,V \]

When a model is trained to predict the next word, letting position \(i\) look at word \(i+1\) would let it copy the answer. The mask puts \(-\infty\) on those scores, and \(e^{-\infty} = 0\), so they get zero weight. Unlike an RNN, all positions are still computed at the same time, in parallel.

Cross-attention

In cross-attention the queries come from one sequence and the keys and values from another. In a translation model, the decoder (writing German) sends queries, and the encoder's outputs (the English sentence) supply the keys and values. So each German position can look at the relevant English words. The formula is the same.

Multi-head attention

One attention computation gives each position one weighted average, so it can follow one kind of relationship at a time (for example "which noun does this pronoun refer to"). Multi-head attention runs \(h\) attention computations, called heads, side by side, each with its own smaller matrices of size \(d\times d_k\). Each head gives an \(n\times d_k\) output. These are concatenated into \(n\times hd_k\) and multiplied by an output matrix \(W_O\) of size \(hd_k\times d\), which brings each row back to length \(d\). The usual choice is \(d_k = d/h\), so the concatenation has length \(d\). The original transformer used \(d = 512\), \(h = 8\) heads and \(d_k = 64\). An exam may choose another \(d_k\) (the 2026 end-sem used \(d = 100\) with 8 heads of size 50), so learn the general count.

Write this in the exam

Count the weights of multi-head attention with \(h\) heads of size \(d_k\) on inputs of size \(d\) (no biases).

  1. Each head has three matrices \(W_Q, W_K, W_V\), each \(d\times d_k\), so \(3dd_k\) weights per head.
  2. The \(h\) heads together have \(3hdd_k\) weights in \(3h\) matrices.
  3. The concatenated output has length \(hd_k\), so \(W_O\) is \(hd_k\times d\), with \(hd_kd\) weights. That makes \(3h + 1\) matrices in all.
  4. Total \(3hdd_k + hd_kd = 4hdd_k\). With \(d_k = d/h\) this is \(4d^2\).
    Why (covers lines 1 to 4, 6 steps)
    1. A query is \(q = W_Q\T x\). It turns \(x\) (length \(d\)) into a vector of length \(d_k\), so \(W_Q\) has \(d\) rows and \(d_k\) columns.
    2. \(W_K\) and \(W_V\) do the same job for keys and values, so each also has \(dd_k\) entries.
    3. Each head has its own three, so multiply by \(h\).
    4. Each head outputs \(d_k\) numbers per token. Placing the \(h\) outputs side by side gives \(hd_k\) numbers.
    5. \(W_O\) maps those \(hd_k\) numbers back to \(d\), so it has \(hd_k\cdot d\) entries.
    6. Add the two parts. \(3hdd_k + hdd_k = 4hdd_k\). Substituting \(hd_k = d\) gives \(4d\cdot d = 4d^2\). The number of tokens \(n\) appears nowhere, because the same matrices are used for every token.

4.12The transformer

Lecture L24 (and the end of L23) · Read: Jurafsky and Martin, Speech and Language Processing, chapter on transformers (many slides come from it)

A transformer block is multi-head self-attention followed by a small MLP applied to each position, each wrapped with a skip connection and layer normalisation. Stack the block \(N\) times.

From words to the first layer's input

  1. A tokenizer splits the text into tokens (words or pieces of words) and gives each an id, for example "I ate an apple <eos>", where <eos> marks the end of the sequence.
  2. An embedding layer (4.10) turns each id into a vector of length \(d\).
  3. A position vector is added to each embedding, because self-attention on its own ignores order (4.11).

Positional encoding

\[ PE(pos, 2i) = \sin\!\left(\frac{pos}{10000^{2i/D}}\right) \]
\[ PE(pos, 2i+1) = \cos\!\left(\frac{pos}{10000^{2i/D}}\right) \]
Reading the formula
  • \(pos\) is the position of the token (0, 1, 2, ...). \(D\) is the embedding length. Dimensions come in pairs \(2i\) and \(2i + 1\), for \(i = 0, 1, \dots, D/2 - 1\).
  • Each pair is a sine and a cosine of the same angle, \(pos/10000^{2i/D}\). For \(i = 0\) the angle grows by 1 per position, a fast wave. For larger \(i\) the denominator is bigger, so the wave is slower. The last pairs change very little across thousands of positions.
  • So the fast pairs tell neighbouring positions apart and the slow pairs tell far-apart regions apart, like the seconds hand and hour hand of a clock. Together they give each position a different vector.
  • It is fixed, not learned, so it works for any length. Learned position embeddings (one learned vector per position) are also common, and the vision transformer uses them.

Example. \(D = 4\), so \(i = 0, 1\) and the denominators are \(10000^0 = 1\) and \(10000^{2/4} = 100\).

  • \(pos = 0\): \((\sin0, \cos0, \sin0, \cos0) \)\({}= (0, 1, 0, 1)\).
  • \(pos = 1\): \((\sin1, \cos1, \sin0.01, \cos0.01) \)\({}\approx (0.841, 0.540, 0.010, 1.000)\).
  • \(pos = 2\): \((\sin2, \cos2, \sin0.02, \cos0.02) \)\({}\approx (0.909, -0.416, 0.020, 1.000)\).

The first pair changes a lot from one position to the next. The second pair barely moves.

These vectors are added to the token embeddings before the first block, as L24 slide 14 shows.

The block

Attention mixes information between positions. The MLP (also called the feed-forward layer) then processes each position on its own, building new combinations of the features that attention gathered.

\[ \operatorname{MLP}(x) = W_2\,\sigma(W_1x + b_1) + b_2 \]

Here \(W_1\) is \(4D\times D\) and \(W_2\) is \(D\times4D\).

Here \(\sigma\) is ReLU in the original transformer and GELU or SiLU in later models (all smooth or piecewise versions of "keep positives, damp negatives").

Layer normalisation rescales each position's vector to mean 0 and standard deviation 1, then applies a learned scale \(\gamma\) and shift \(\beta\).

\[ \operatorname{LayerNorm}(x) = \gamma\odot\frac{x - \mu}{s} + \beta \]

where \(\mu\) is the mean and \(s\) the standard deviation of the \(D\) entries of \(x\).

\[ \mu = \frac1D\sum_{m=1}^D x_m \]
\[ s = \sqrt{\frac1D\sum_{m=1}^D (x_m - \mu)^2} \]
Reading the formula

\(\mu\) (mu) is the average of the \(D\) entries of one token's vector, and \(s\) is their standard deviation. Subtracting \(\mu\) centres the entries on 0, and dividing by \(s\) makes their spread 1. \(\gamma\) (gamma) and \(\beta\) (beta) are learned vectors of length \(D\), so the network can undo the scaling if that helps. \(\odot\) multiplies entry by entry.

Example with \(\gamma = 1\), \(\beta = 0\). For \(x = (2, 4, 6)\), \(\mu = 4\). The centred entries are \((-2, 0, 2)\), with mean square \(8/3\), so \(s = \sqrt{8/3} \approx 1.633\). The output is \((-1.225, 0, 1.225)\).

Lines 3 and 6 of the block below apply it, and the first practice question works a four-entry example.

It is like the batch normalisation of the neural networks page, but the mean and standard deviation are taken over the \(D\) features of one token, not over the batch. So it works the same for any batch size and any sequence length.

With these pieces, one block (as in the 2017 paper, called post-norm) is

  1. \(T_1 \)\({}= \operatorname{MultiHeadAttention}(X)\)
  2. \(T_2 = X + T_1\) (skip connection)
  3. \(T_3 \)\({}= \operatorname{LayerNorm}(T_2)\)
  4. \(T_4 = \operatorname{MLP}(T_3)\), applied to each row
  5. \(T_5 = T_3 + T_4\) (skip connection)
  6. \(H \)\({}= \operatorname{LayerNorm}(T_5)\)

The output \(H\) has the same shape as the input \(X\) (\(n\times D\)), so blocks can be stacked. The skip connections play the same role as in ResNet (4.6). They give the gradient a direct path through a deep stack.

Pre-norm moves the normalisation inside each branch, giving \(X + \operatorname{MHA}(\operatorname{LN}(X))\) and then the same with the MLP. The skip path then carries \(X\) completely untouched from the bottom of the stack to the top, which makes gradients better behaved, and most models since about 2020 use it. L24 slide 16 compares the 2017 transformer with LLaMA (2023). Post-norm became pre-norm, LayerNorm became RMSNorm (\(x/\operatorname{RMS}(x)\cdot g\), with \(\operatorname{RMS}(x) \)\({}= \sqrt{\frac1n\sum x_i^2}\)), ReLU became SiLU (\(x\,\sigma(x)\)), and sinusoidal positions became RoPE (rotary position encoding, which rotates query and key vectors by an angle that depends on position). You only need to know these names and what each replaces.

The original transformer was built for translation and has both. Each decoder block has three sub-layers. The first is masked self-attention over the output so far. The second is cross-attention with queries from the decoder and keys and values from the final encoder output (the same for every decoder block, L24 slide 24). The third is the MLP. Each sub-layer has its skip connection and normalisation.

Generating text by autoregressive decoding

Autoregressive means each output is fed back in as input for the next step. To translate "I ate an apple", the decoder starts with a start token <sos> and predicts "Ich". Then it sees "<sos> Ich" and predicts "habe", and so on until it predicts <eos>.

During training, the correct German sentence is known. So instead of feeding back the model's own guesses, all the correct previous words are fed in at once (the target "shifted right" by one place), and the causal mask stops each position from seeing its own answer. This is called teacher forcing, and it lets all positions be trained in parallel. During generation there is no correct sentence, so the steps really are one at a time.

The language modelling head

The last block gives a vector \(h_N\) (length \(D\)) at the current position. The language modelling head turns it into a probability for every word in the vocabulary.

\[ u = h_N E\T, \qquad y = \operatorname{softmax}(u) \]

\(E\) is the \(V\times D\) embedding matrix from the input, reused here (this is called weight tying), so \(u\) has one score per word, \(V\) in all. These scores are called logits. Then choose the next word. Greedy decoding takes the most probable word, and sampling draws a word at random according to \(y\).

Remember
  • Input = token embedding + position encoding. The sinusoidal encoding uses \(\sin\) and \(\cos\) of \(pos/10000^{2i/D}\).
  • Block: attention, add, norm, MLP (\(D\to4D\to D\)), add, norm. Output shape = input shape.
  • Weights per block: \(4D^2\) (attention) + \(8D^2\) (MLP) \(\approx 12D^2\).
  • Encoder sees everything (BERT). Decoder is masked and autoregressive (GPT). Cross-attention takes Q from the decoder and K and V from the final encoder output.
  • Teacher forcing: train on the correct previous tokens, all positions at once, with the causal mask.

4.13The vision transformer

Lecture L24, slides 32 to 35 · Paper: Dosovitskiy et al., "An image is worth 16×16 words" (ICLR 2021)

Cut the image into square patches, flatten each patch into a vector, project it to length \(D\), add a learned position embedding, and feed the patches to an ordinary transformer encoder as if they were words.

  1. Split the \(224\times224\times3\) image into \(16\times16\) patches. There are \(224/16 = 14\) patches across and 14 down, so \(14\times14 = 196\) patches.
  2. Flatten each patch into \(3\times16\times16 = 768\) numbers.
  3. Multiply by a learned \(768\times D\) matrix to get a \(D\)-dimensional token. This is the same as a convolution with \(16\times16\) filters and stride 16.
  4. Add a learned position embedding to each token.
  5. Put an extra learned token, the [CLS] token (for "class"), at the front. That makes 197 tokens.
  6. Run the transformer encoder. The output vector at the [CLS] position goes through a small MLP head to give the class.

Compared with a CNN, a vision transformer has no built-in idea that nearby pixels are related (no locality or weight sharing over space beyond the patch). Every patch can attend to every other patch from the first layer. It needs more training data to learn what a CNN gets for free, and with enough data (hundreds of millions of images) it matches or beats CNNs.

Remember
  • Number of patches = \((H/P)\times(W/P)\). Each patch has \(C\cdot P\cdot P\) numbers.
  • \(224\times224\) with \(16\times16\) patches: 196 patches of 768 numbers, plus [CLS] = 197 tokens.
  • Position embeddings in ViT are learned. Classification uses the [CLS] output.

4.14Self-supervised learning, BERT and GPT

Lecture L25, slides 21 to 54

Self-supervised learning invents a labelled task from unlabelled data (hide part of the input and predict it), trains a big network on it, and reuses that network for the tasks you actually care about.

Labels are expensive. Someone has to tag each image or sentence. Unlabelled text and images are almost free and enormous. Self-supervised learning (SSL) builds a supervised task out of unlabelled data, so the data supervises itself. L25 slide 26 gives the general idea, which is to pretend that some part of the data is unknown and train the network to predict it.

The made-up task is called a pretext task. Nobody cares about its answers. What matters is that solving it forces the network to learn useful features. The task you care about later is the downstream task.

The slides name two families. Self-prediction hides part of one sample and predicts it. Contrastive learning compares several samples and predicts their relationship (same or different), which is section 4.15.

Pretext tasks for images

  • Rotation. The network can only tell which way is up if it knows what objects normally look like, for example that eyes are above mouths.
  • Relative patch position. Given a centre patch and one of its 8 neighbours, predict which neighbour it is (L25 slide 50).
  • Jigsaw. Predict the correct order of shuffled tiles.
  • Inpainting. Blank out a region and reconstruct its pixels (L25 slides 52 and 53).
  • Colourisation. Give a grey image and predict its colours (slide 54). To colour a banana yellow, the network must recognise it as a banana.

Pretext tasks for text, BERT and GPT

Text has natural pretext tasks. A model can predict a missing word from its neighbours (word2vec, 4.10), predict masked words, predict whether two sentences are in the right order, or predict the next word.

  • BERT (Bidirectional Encoder Representations from Transformers, 2018) is a transformer encoder. It is pretrained with masked language modelling: hide about 15 percent of the tokens with a [MASK] token and predict them from both sides (hence "bidirectional"), and with next sentence prediction (is sentence B the real next sentence after A). To fine-tune, add a small layer on top, for example a classifier on the output at the [CLS] position.
  • GPT (Generative Pretrained Transformer) is a transformer decoder pretrained to predict the next word, with the causal mask. GPT-3 (2020) has 175 billion parameters, 96 blocks and \(D = 12{,}288\). Instead of fine-tuning, tasks can be given as text, the prompt (for example "Summarize this article: ... The summary is:"), and the model continues it.

Pretrain, then fine-tune

The resulting paradigm (L25 slides 29 and 45) has two stages. Pretraining learns general features from a large, general, often unlabelled dataset. This is expensive and done once, and the result is called a foundation model. Fine-tuning continues training on a small labelled dataset for the specific task, starting from the pretrained weights. It is cheap and needs little data.

Fine-tuning every weight of a billion-parameter model is still costly, and each task would need its own full copy. Parameter-efficient fine-tuning freezes the pretrained weights and trains only a few new ones. In LoRA (low-rank adaptation), a frozen weight matrix \(W\) of size \(d\times k\) is used as \(W + BA\), where \(B\) is \(d\times r\) and \(A\) is \(r\times k\) with a small rank \(r\) (this is the low-rank idea from the SVD part of the course). Only \(A\) and \(B\) are trained. BitFit trains only the biases.

Reading the formula

The layer computes \((W + BA)x\). \(W\) has \(d\cdot k\) entries and stays fixed. \(B\) has \(d\cdot r\) and \(A\) has \(r\cdot k\), so LoRA trains \(dr + rk\) numbers. The product \(BA\) has the same shape as \(W\), so it can be added to it, but its rank is at most \(r\).

Example. \(d = k = 10\) and \(r = 1\). \(W\) has 100 entries. \(B\) is \(10\times1\) and \(A\) is \(1\times10\), so LoRA trains 20 numbers, a fifth of the full count.

  • BERT = encoder, masked language modelling, understanding. GPT = decoder, next word, generation.
  • Pretrain (big, general, once) then fine-tune (small, specific). LoRA trains \(BA\) of rank \(r\) beside a frozen \(W\).

4.15Contrastive learning, Siamese networks and LMNN

Lecture L25, slides 55 to 65

Learn an embedding in which similar pairs are close and dissimilar pairs are far apart. Two copies of the same network (a Siamese network) map the two items, and the loss pulls or pushes their embeddings.

Often we do not know the class of an item, but we do know that two items are the same thing (two photos of the same object, two crops of the same image) or different things. Contrastive learning uses only that. The goal (L25 slide 59) is an embedding space where similar samples stay close and dissimilar ones are far apart. Then nearest-neighbour search in that space (the very first algorithm of the course) works well.

In self-supervised contrastive learning the positives are made by augmentation: two random crops, colour changes or flips of the same image count as "the same", and other images count as "different". The slide on videos gives another free source of pairs. The same face tracked across frames is one person (positive), and two faces in the same frame must be different people (negative).

Siamese networks and the contrastive loss

A Siamese network is one network applied to two inputs (two copies with the same weights, like twins, hence the name). The distance between the outputs is

\[ D_W(X_1, X_2) = \|G_W(X_1) - G_W(X_2)\| \]

The loss of Hadsell, Chopra and LeCun (2006), whose general form is on the slide, uses a squared distance for similar pairs and a margin \(m\) for dissimilar ones.

Name the two parts first, as the slide does, a loss \(L_S\) for similar pairs and \(L_D\) for dissimilar pairs.

\[ L_S = \tfrac12 D_W^2 \]
\[ L_D = \tfrac12\big(\max(0,\, m - D_W)\big)^2 \]
\[ L = (1 - Y)\,L_S + Y\,L_D \]
Reading the formula
  • If \(Y = 0\) (similar), only the first term is left, \(\frac12D_W^2\). It is smallest when the two embeddings coincide, so the pair is pulled together.
  • If \(Y = 1\) (dissimilar), only the second term is left. If the pair is already at least \(m\) apart, \(m - D_W \le 0\), the max gives 0 and there is no loss. If it is closer than \(m\), it is pushed apart.
  • The margin is needed because, without it, the loss would reward pushing dissimilar pairs infinitely far, and that term could dominate training. With it, "far enough" is enough.

Example with \(m = 2\). A similar pair at \(D_W = 0.5\) gives \(\frac12(0.25) = 0.125\). A dissimilar pair at \(D_W = 0.5\) gives \(\frac12(2 - 0.5)^2 \)\({}= \frac12(2.25) \)\({}= 1.125\). A dissimilar pair at \(D_W = 3\) gives \(\max(0, -1) = 0\), so no loss.

The triplet loss below uses the same margin idea with three items, and the second practice question uses this formula.

A closely related loss uses three items at once, an anchor \(a\), a positive \(p\) and a negative \(n\). The triplet loss asks the negative to be farther than the positive by at least a margin \(\alpha\).

Write \(d_p = \|f(a) - f(p)\|^2\) for the squared distance to the positive and \(d_n = \|f(a) - f(n)\|^2\) for the negative. Then

\[ L = \max(0,\; d_p - d_n + \alpha) \]
Reading the formula

\(f\) is the embedding network. The loss is 0 once the negative is farther than the positive by at least \(\alpha\) (alpha), that is when \(d_n \ge d_p + \alpha\). Otherwise it is the amount by which that condition fails, and the gradient pulls \(p\) towards \(a\) and pushes \(n\) away.

Example with \(\alpha = 0.5\). If \(d_p = 1\) and \(d_n = 3\), then \(1 - 3 + 0.5 = -1.5\), so \(L = 0\). If \(d_p = 1\) and \(d_n = 1.2\), then \(L = 1 - 1.2 + 0.5 = 0.3\).

The first practice question below uses it, and person identification (next paragraph) is trained with it.

Slide 64 applies this to person identification. Two photos of the same person from different cameras should embed close together, so a new photo can be matched by nearest neighbour.

LMNN

Large margin nearest neighbour (LMNN, Weinberger and Saul, 2009) is the same idea before deep learning. It learns a linear map \(L\) and measures distance as \(\|L(x_i - x_j)\|\) (a Mahalanobis distance, from the foundations page). For each point it picks a few target neighbours of the same class and pulls them close. Any point of a different class that comes inside the target neighbours' distance plus a margin is an impostor, and it is pushed out. After training, \(k\)-NN with the learned distance makes fewer mistakes. The deep versions above simply replace the linear map \(L\) with a neural network \(G_W\).

Remember
  • Goal: an embedding where similar pairs are close and dissimilar pairs are at least a margin apart.
  • Siamese network: one network with shared weights on both inputs. \(D_W = \|G_W(X_1) - G_W(X_2)\|\).
  • Contrastive loss: \((1-Y)\frac12D_W^2 + Y\frac12\max(0, m - D_W)^2\), with \(Y = 1\) for dissimilar.
  • Triplet loss: \(\max(0, d(a,p)^2 - d(a,n)^2 + \alpha)\). LMNN pulls target neighbours in and pushes impostors out, for better \(k\)-NN.

PracticeWhy must the two branches of a Siamese network share their weights?›
  1. The distance \(D_W\) should depend only on the two inputs, not on which input went into which branch. With shared weights, swapping \(X_1\) and \(X_2\) gives the same distance.
  2. Two identical inputs should have distance 0. With shared weights \(G_W(X) - G_W(X) = 0\) always. With different weights this would not hold.
  3. After training we want one embedding function to apply to any new item (for example a new face photo) and compare it with stored embeddings. Shared weights give exactly one such function, and half as many parameters to learn.

Quick checks on the answer

  • An output size is a whole number. With stride 1 and "same" padding it equals the input size.
  • The number of output channels equals the number of filters. Pooling keeps the channels and adds no parameters.
  • A conv layer's parameter count does not depend on the image size. A multi-head layer's count does not depend on the number of tokens.
  • Each row of attention weights lies between 0 and 1 and adds up to 1. With a causal mask, every weight above the diagonal is 0.
  • The attention output has one row per token, so its shape is \(n\times d_v\).
  • LSTM gates lie between 0 and 1, the candidate lies between −1 and 1, and \(|h_t| \lt 1\).
  • A cosine similarity lies between −1 and 1. A layer-normalised vector has mean 0.
  • Contrastive and triplet losses are never negative.
  • For a vision transformer, patches times patch length equals height times width times channels.

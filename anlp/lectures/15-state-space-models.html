Lecture 15 · 48 slides

State space models: train like a convolution, generate like an RNN.

A Transformer pays for its perfect memory with a KV cache that grows with every token and attention that costs O(L2). State space models keep a fixed-size state instead. This lecture starts from the continuous-time SSM of control theory, turns it into a recurrence you can run token by token and a convolution you can train in parallel, shows how HiPPO and S4 gave that state a memory that lasts, and ends with Mamba, which lets each token decide what the state keeps.

Lecture 15 48 slides Manish Shrivastava · Aparajitha

§0The deck at a glance

The deck has four numbered parts. Slides 1–2 place the lecture right after the one on modern RNNs. Part 1 (slides 3–5) asks why we need anything beyond Transformers and answers with the Long Range Arena benchmark and a table of what each classic sequence model gets wrong. Part 2 (slides 6–19) builds the state space model from scratch. It starts as a differential equation, gets discretized into a linear recurrence, and turns out to be a long convolution too. Then it becomes a layer you can stack, and the part ends with why the naive version does not work. Part 3 (slides 20–29) fixes the two problems. HiPPO picks an A matrix that remembers, S4 computes the convolution kernel fast, and S4D shows that a diagonal A is enough. H3 then shows that these models still fall short on language. Part 4 (slides 30–43) is Mamba. It makes the SSM's parameters depend on the input, pays for that with a hardware-aware parallel scan, and wraps it into one block. Slides 44–48 compare all the models, list the takeaways and give reading material.

One distinction runs through the whole lecture, so it is worth fixing now. If the SSM's matrices are the same at every time step (a linear time-invariant, or LTI, system), the model can be computed as a convolution and trained fast, but it treats every token the same way. If the matrices change with the input, as in Mamba, the model can choose what to remember, but the convolution is gone and you need a scan instead. S4 sits on one side of this line and Mamba on the other.

⚠ Notation

The deck uses two notations. Up to slide 29 (following S4), the input is u, the state is x and the output is y. From slide 33 on (following Mamba), the input is x and the state is h. The borrowed diagrams on slides 7, 10–12, 26 and 40 already use the Mamba letters. Same model, different letters.

§1Why state space models

Every sequence model before this lecture gives up something. RNNs train slowly and forget, CNNs see only a window, and Transformers cost L2. SSMs are pitched as a way to keep the good parts of all three.

slide 02 · recap and plan

On the slide

A recap of the previous lecture on RNNs and the plan for this one. The deck numbers the previous lecture "L20". In this guide it is Lecture 14, RNN Advances.

Why the recap matters here

The left column is the whole motivation in four lines. A model with a fixed-size state needs the same memory for token 10 and for token 100,000, because it never looks back at old tokens. It only updates its state. A Transformer, by contrast, keeps every key and value it has seen. If the state update is linear in the state, training can still run in parallel using a scan. SSMs are exactly such linear recurrences, but they come with a theory, borrowed from signal processing, for choosing the recurrence so that the state remembers far back.

The last bullet is the price, and it comes back at the end of the lecture. A state of fixed size can only hold so much, so a recurrent model cannot recall arbitrary old details the way attention can.

⚠ Watch out

Items 5 and 6 of the plan (Mamba-2 and the 2025–26 models) do not get their own slides in this deck. They appear only in the comparison table on slide 44 and the takeaways on slide 45, so this guide covers them there.

Slide 04 / 48
slide 04 · Long Range Arena and Path-X

On the slide

Long Range Arena (LRA) is a benchmark of six tasks with sequences of 1K to 16K steps. The hardest, Path-X, flattens a 128 × 128 image into a sequence of 16,384 pixels and asks whether two dots are joined by a dashed path. No Transformer variant did better than coin-flipping on it.

Why Path-X is so hard for a sequence model

A person solves this by tracing the line with their eye. A sequence model sees the image one pixel at a time, row by row. Two neighbouring pixels of the same dash can be 128 steps apart (one row up), and the two dots can be more than 10,000 steps apart. To answer, the model has to combine evidence spread over the whole sequence, with no local shortcut.

For a Transformer, length itself is the first problem. One attention matrix over 16,384 tokens has 16,3842 ≈ 2.7 × 108 entries, about 1.1 GB in FP32 for a single head in a single layer. The "efficient Transformers" in LRA approximate attention to fit, and on Path-X none of them learned anything.

✦ Key takeaway

Path-X is the benchmark to remember. Slide 25 shows S4 as the first model to solve it, which is what put SSMs on the map.

Slide 05 / 48
slide 05 · what each family gets wrong

On the slide

A scorecard of RNNs, CNNs and Transformers on four properties, and the wish list that SSMs are meant to meet. The wish is parallel training, constant cost and memory per generated token, and long context.

Reading the table row by row

  • RNN / LSTM. Generation is cheap because the state has a fixed size. But step t needs the state from step t − 1, so training cannot run over positions in parallel, and gradients through many steps vanish (the problem LSTMs were built to soften, not solve).
  • CNN. All positions are computed at once, which is great for training. But each output sees only a window of inputs, so anything older than the window is invisible.
  • Transformer. Parallel and sees everything. But attention compares every pair of tokens, so training costs O(L2), and generating token L means reading a KV cache of length L.

The SSM promise in the callout is a direct answer. The same model will be computed as a convolution during training (the CNN column) and as a recurrence during generation (the RNN column). Slides 15–17 show why one model can be both. "Principled long memory" refers to HiPPO in Part 3.

§2The state space model

Before any deep learning, an SSM is a pair of equations from control theory. A hidden state evolves over time, input pushes on it, and the output is read off it.

slide 06 · part 2 divider

On the slide

Section divider for Part 2, which builds the SSM from scratch.

Slide 07 / 48
slide 07 · a map from signal to signal

On the slide

An SSM takes a continuous input signal and produces a continuous output signal. This diagram uses x(t) for the input, as Mamba does.

What "continuous" buys you

Text is not continuous. It is a list of tokens. The trick of the whole lecture is to define the model on continuous time first and only then sample it at the token positions. The continuous view is where the good choices come from (which matrix gives long memory, slide 23), and the sampled view is what you actually compute (slide 14).

Slide 08 / 48
slide 08 · continuous, recurrent, convolutional

On the slide

Three properties of SSMs, from Albert Gu's thesis. They are continuous (a differential equation), recurrent (they can be stepped one token at a time with constant memory) and convolutional (an LTI SSM is a convolution, which trains in parallel).

Why each one matters

  • Continuous. Because the model lives in continuous time, the sampling step is a parameter you choose. If samples arrive twice as fast, you halve the step. Mamba later turns this step into something each token sets for itself.
  • Recurrent. This is the RNN column of slide 5. Constant cost per token at generation time.
  • Convolutional. This is the CNN column, with one difference. The convolution kernel is as long as the whole sequence, so there is no window limit.

Keep in mind that the third property needs the system to be time-invariant. Slide 16 makes that precise, and slide 33 is where Mamba gives it up.

Slide 09 / 48
slide 09 · the two equations

On the slide

x′(t)= Ax(t)+Bu(t) y(t)= Cx(t)+Du(t)

The first equation says how fast the state changes. The second says how to read the output.

Shapes, for one channel

SymbolShapeJob
u(t)scalarthe input at time t
x(t)Nthe state, the model's memory
AN × Nhow the state changes on its own (decay, rotation, mixing)
BN × 1how the input is written into each state dimension
C1 × Nhow the state dimensions are combined into the output
Dscalara direct path from input to output

A one-number example

Take N = 1, A = −1, B = 1 and no input. The equation x′ = −x says the state shrinks at a rate equal to its size, so it decays exponentially, x(t) = x(0) e−t. A negative A means "forget slowly". A more negative A forgets faster. If A were positive the state would blow up. With N state dimensions, A can hold many decay speeds at once, and that is how the state remembers both recent and older input.

⚠ Watch out

One SSM maps one scalar signal to one scalar signal. A language model has H channels (the hidden size), so the layer runs H independent SSMs side by side, one per channel. The N here is the state size per channel, not the model width. Slide 18 shows how the channels then get mixed.

Slide 10 / 48
slide 10 · state equation and output equation

On the slide

The same two equations with their names. The state equation updates the memory, the output equation reads it.

How to think about the split

The split is the same as in an RNN. Writing to memory and reading from memory are separate steps with separate parameters. B controls writing, C controls reading, and A controls what happens to the memory in between. Mamba will later make B and C depend on the current token, so the model can decide per token what to write and what to read.

Slide 11 / 48
slide 11 · the equations as matrix pictures

On the slide

The same two equations drawn as coloured matrices, from Grootendorst's visual guide. Here the state is called h and the input x.

What the picture adds

It labels each term with its job, which is the useful part. A times the state is "how the current state evolves", B times the input is "how the input influences the state", C times the state is "how the state becomes the output", and D times the input is the shortcut. The grids are schematic. The diagram draws the state as a grid and A as larger than N × N, which you should not read as real shapes. Use the table on slide 9 for that.

Slide 12 / 48
slide 12 · the SSM as a block diagram

On the slide

The SSM as a signal-flow diagram. The input goes through B into the state, the state loops back to itself through A, the state goes out through C, and D skips the state entirely.

Why the loop matters

The loop through A is where memory lives. Without it the state would be just B times the current input, and the model would see one time step only. With it, every past input keeps circulating, scaled by A each time around. Whether it fades, persists or explodes depends on A, which is the question Part 3 answers.

The D path is a residual connection inside the layer. In practice it is often dropped, because the block around the SSM already has a residual (slide 18).

Slide 13 / 48
slide 13 · mass on a spring

On the slide

A physical system written as an SSM. A mass on a spring with friction is pushed by a force u(t). The state is its position and velocity, and the output is its position.

Reading each matrix

With k = 40, b = 5, m = 1 as on the slide,

  • A = [[0, 1], [−40, −5]]. The first row says "the rate of change of position is the velocity". The second row says "the velocity changes by −40 × position (the spring pulls back) and −5 × velocity (friction slows it)".
  • B = [0, 1]⊤. The force changes only the velocity directly (Newton's F = ma). Position changes only because velocity does.
  • C = [1, 0]. The output picks the first state entry, the position, and ignores velocity.

What the plot shows

Each push of force (top) moves the mass, and the position (bottom) keeps responding after the force has stopped. That lag is the point. The output at time t depends on inputs from earlier, carried forward by the state. A sequence model wants exactly this, with A, B, C learned instead of set by physics.

§3Discretization and the two views

Tokens arrive at discrete steps, so the continuous model has to be sampled. Once sampled, the same model can be computed in two ways, and the lecture uses each for a different job.

Slide 14 / 48
slide 14 · zero-order hold and the step size Δ

On the slide

To get a sequence model, sample the signal every Δ time units and convert (Δ, A, B) into discrete matrices (Ā, B̄). Mamba uses the zero-order hold rule

A¯= eΔA B¯= (ΔA)−1 (eΔA−I) ΔB

Where the formula comes from

"Zero-order hold" means you assume the input stays constant between two samples. Over one step of length Δ with no input, the state equation x′ = Ax is solved by x(t + Δ) = eΔA x(t). That is Ā, the factor by which the old state survives one step. B̄ is how much of a constant input accumulates in the state over the same step, which is what the integral of esAB over the step works out to.

Worked example with one state dimension

Take A = −1 and B = 1. Then Ā = e−Δ and B̄ = 1 − e−Δ.

ΔĀ (old state kept)B̄ (new input written)
0.010.9900.010
0.10.9050.095
20.1350.865
50.0070.993

This is the callout on the slide in numbers. A small step means little time passes, so the state barely changes and the input barely gets in. A large step means a lot of time passes, so the old state decays away and the state is mostly the new input. Here the two columns always add to 1, so the update is a weighted average of old state and new input. Keep this table in mind for slide 34.

⚠ Watch out

The intuition "Δ small means long memory" only holds when A is stable (its eigenvalues have negative real parts, like −1 here). Also note that Δ is learned. Discretization is not a preprocessing step done once. It is the first computation inside the layer's forward pass, so gradients flow into Δ, A and B through it.

Slide 15 / 48
slide 15 · the recurrent view

On the slide

After discretization the SSM is a recurrence, xk = Ā xk−1 + B̄ uk and yk = C xk. It is an RNN whose update has no nonlinearity.

Cost per token

Each new token needs one matrix–vector product Ā x (N × N times N, so N2 multiplications) plus two vector operations. With N = 64 that is 4,096 multiplications for a dense Ā, or 64 if Ā is diagonal (each state entry just gets scaled by its own number). Either way the cost does not depend on how many tokens came before. Compare a Transformer, where token L attends over all L cached keys.

Why "no nonlinearity" is the key word

A classic RNN computes tanh(W h + U x). Because of the tanh, you cannot know h100 without computing h1 to h99 in order. A linear update can be unrolled into a closed formula, which is what makes the convolution on the next slide (and the parallel scan on slide 37) possible. The nonlinearity moves out of the recurrence and into the layers around it (slide 18).

Slide 16 / 48
slide 16 · the convolutional view

On the slide

Unroll the recurrence and every output is a weighted sum of all past inputs, with weights CB̄, CĀB̄, CĀ2B̄, … These weights form a kernel K̄ as long as the sequence, and the output is the convolution y = K̄ ∗ u.

Worked example: both views give the same answer

Use one state dimension with Ā = 0.5, B̄ = 1, C = 2 and inputs u = (1, 2, 3).

Recurrence. Start from x = 0.

  • k = 0: x = 0.5·0 + 1 = 1, y = 2
  • k = 1: x = 0.5·1 + 2 = 2.5, y = 5
  • k = 2: x = 0.5·2.5 + 3 = 4.25, y = 8.5

Convolution. The kernel is K̄ = (CB̄, CĀB̄, CĀ2B̄) = (2, 1, 0.5). Then y2 = 0.5·u0 + 1·u1 + 2·u2 = 0.5 + 2 + 6 = 8.5. The same as the recurrence.

The kernel reads naturally. The most recent input gets weight 2, one step back gets 1, two steps back gets 0.5. Each step into the past multiplies by Ā once more. That is the memory decaying.

Why this helps training

The recurrence needs L steps in order. The convolution computes all L outputs at once, and with the FFT it costs O(L log L) instead of the O(L2) of summing directly. That fills the "parallel training" column of slide 5.

✦ Key takeaway

The convolution exists only because the same Ā, B̄, C are used at every step. If B̄ were different at step 1 and step 2, the weight on u1 would not be the same number for every output, and there would be no single kernel. This is the property Mamba trades away on slide 33.

Slide 17 / 48
slide 17 · one model, three views

On the slide

Figure 1 of the S4 paper. The same SSM as a continuous system, a recurrence and a convolution, with the question of long-range memory in the middle.

The practical rule

During training you have the whole sequence, so use the convolution and compute every position in parallel. During generation tokens arrive one at a time, so switch to the recurrence and keep only the N-dimensional state. The parameters are the same in both modes. Only the algorithm changes.

The middle panel is the open question. Nothing so far says how to choose A. A random one gives a kernel that either dies out after a few steps or blows up, so the model still cannot reach far back. The lower-triangular matrix drawn there hints at the answer, the HiPPO matrix of slide 23.

Slide 18 / 48
slide 18 · the SSM block

On the slide

How an SSM becomes a layer. Normalize, run H independent SSMs (one per channel), apply GELU, mix channels with a linear layer, add the residual. Then stack these blocks like Transformer blocks.

Shape bookkeeping

Say L = 1,024 tokens, H = 256 channels and N = 64.

  • Input: L × H = 1,024 × 256.
  • SSM step: channel h is a length-1,024 signal. Its own SSM (its own A, B, C, Δ) maps it to another length-1,024 signal. Channels do not talk to each other here. Output: still 1,024 × 256.
  • GELU, then the linear layer. Each token's 256-vector is multiplied by a 256 × 256 matrix, and tokens do not talk to each other here.

So the two parts split the work cleanly. The SSM moves information along time, within a channel. The linear layer moves information across channels, within a token. This is the same split as attention (mixes tokens) and the MLP (mixes features) in a Transformer block from Lecture 2.

Under the hood

The SSM itself is linear. All of the network's nonlinearity comes from the GELU and the gating around it. That is the deal that makes the convolution and the scan possible. Keep the time mixing linear and put the nonlinearity between layers.

Slide 19 / 48
slide 19 · why the naive SSM fails

On the slide

The plain SSM does not work as is. It is slow, it forgets like an RNN, and storing or computing the full state sequence is too expensive.

Where the costs come from

Running the recurrence over L steps with a dense N × N matrix Ā costs N2 per step, so N2L in total. Keeping all L states (needed for the backward pass) takes NL memory, per channel. The convolution view does not escape either, because building the kernel needs Ā0, Ā1, …, ĀL−1, which is the same chain of L matrix products.

The forgetting problem is the same one LSTMs were invented for. The kernel entries are CĀkB̄, and powers of a matrix either shrink to zero or grow without bound as k grows. Slide 21 turns these two complaints into the two problems Part 3 solves.

§4HiPPO and S4

Two fixes turn the basic SSM into a working layer. HiPPO answers which A to use so the state remembers. S4 answers how to compute the long kernel quickly and stably once A has that structure.

Slide 21 / 48
slide 21 · two obstacles

On the slide

Two problems stand between the basic SSM and a useful layer. The modelling problem is which A gives long memory. The compute problem is how to get the kernel K̄ without L matrix products.

The modelling problem in numbers

Think of one state dimension with Ā = λ. The kernel weight on an input k steps back is proportional to λk. With λ = 0.9, after 100 steps the weight is 0.9100 ≈ 2.7 × 10−5, effectively zero. With λ = 1.1 it is about 1.4 × 104, which swamps everything. Path-X needs memory over thousands of steps, and a random A gives you neither.

The evidence on the slide is striking. The architecture was unchanged and only the initial A was swapped for the HiPPO matrix. Accuracy on sequential MNIST (classifying a digit fed in pixel by pixel, 784 steps) went from 60% to 98%.

The compute problem

This is slide 19's cost again. HiPPO's A is not diagonal, so computing Āk for every k up to L is slow, and repeated multiplication also loses precision. S4 is the algorithm that gets around this (slide 24).

Slide 22 / 48
slide 22 · memory as polynomial approximation

On the slide

HiPPO's idea is to define memory as approximation. At every moment, fit a polynomial to the entire input history so far. The N coefficients of that polynomial are the state. HiPPO works out an ODE that keeps those coefficients correct as new input arrives, and that ODE has exactly the SSM form.

Why this is a good definition of memory

Suppose you may store only N numbers about a long signal. A natural choice is the N coefficients of the best degree-(N − 1) polynomial fit to it. From those you can redraw an approximate version of the whole history, smooth but recognisable. The question HiPPO solves is how to update those coefficients when one more input arrives, without refitting from scratch. The answer is a linear update, c′(t) = A c(t) + B f(t). That is an SSM, so this "best polynomial memory" can be dropped straight into the layer of slide 18 by using HiPPO's A and B.

In the figure, the red and blue shaded regions are the weightings (measures) used at two times t0 and t1. The blue one covers the whole history up to t1, which is what "scaled" in HiPPO-LegS on the next slide means. The window grows with time, so nothing is ever cut off.

Slide 23 / 48
slide 23 · the HiPPO-LegS matrix

On the slide

The formula for the HiPPO-LegS matrix that S4 uses to initialise A (the minus sign applies to all three cases).

Worked example, N = 3

Index rows n and columns k from 0. Entries above the diagonal are 0, the diagonal is −(n + 1), and below the diagonal it is −√(2n + 1)·√(2k + 1).

k = 0k = 1k = 2
n = 0−100
n = 1−√3 ≈ −1.73−20
n = 2−√5 ≈ −2.24−√15 ≈ −3.87−3

What to notice

  • Lower-triangular. Coefficient n is updated using only coefficients 0 to n. The low-order coefficients (the coarse shape of the history) do not depend on the fine detail.
  • Stable. For a triangular matrix the eigenvalues are the diagonal entries, here −1, −2, −3. All negative, so the state never blows up. Compare slide 21, where a random matrix could have eigenvalues anywhere.
  • Fixed. It is a formula, not something learned from data. S4 uses it as the starting value of A and training adjusts it from there.

The plot shows what the state means. Each bar is one coefficient, each blue curve is the Legendre polynomial it multiplies, and the red curve is their weighted sum, an approximate redraw of the input history. That is the sense in which the state "remembers" the past.

Slide 24 / 48
slide 24 · S4's fast kernel (optional)

On the slide

How S4 computes the kernel K̄ for the HiPPO matrix without L matrix powers. The slide marks it optional.

The idea in plain terms

Computing CB̄, CĀB̄, CĀ2B̄, … one by one is the slow part. S4 avoids it in three moves.

  1. Instead of the kernel entries themselves, compute a sum of all of them weighted by powers of a number z. A geometric series of matrices sums to a single inverse, (I − Āz)−1, so L powers become one inverse. Doing this at L special values of z and applying an inverse FFT recovers the kernel.
  2. If A were diagonal, that inverse would be trivial, a sum of simple fractions (the Cauchy kernel).
  3. HiPPO is not diagonal, but it is diagonal minus a low-rank piece. The Woodbury identity corrects the diagonal result for the low-rank piece cheaply.

The outcome is a kernel computed in roughly O(N + L) time and memory instead of O(N2L). As the slide says, you can use S4 without following this derivation. What matters for the rest of the lecture is the conclusion that structure in A buys speed. Slide 28 shows that dropping the low-rank part entirely works almost as well, which removes most of this machinery.

On the slide

The LRA results table from the S4 paper. S4 wins every task and is the only model that does better than chance on Path-X.

How to read it

  • Average. The best Transformer variant (Luna-256) averages 59.37. S4 averages 86.09, a gap of almost 27 points.
  • Path-X. Every other row has ✗, meaning about 50%, a coin flip. S4 gets 96.35%. This is the slide 4 benchmark that no Transformer could learn.
  • Image. This task is CIFAR images fed pixel by pixel. S4 gets 88.65 against at most 47.38 for the others. Long sequences of smooth, signal-like data are where an SSM's continuous-time origin helps most.

⚠ Watch out

LRA is not language modelling. Its tasks reward smooth long-range signal processing. S4's success here does not mean it is good at text, and slides 27 and 29 show that it is not.

Slide 26 / 48
slide 26 · S4 = SSM + HiPPO + discretization

On the slide

S4 summed up as three ingredients. The SSM equations, the HiPPO matrix for memory, and discretization, which allows convolutional training and recurrent inference.

Putting the three together

Each ingredient solves one problem from earlier. The SSM gives a linear recurrence. HiPPO's A makes the state a compressed record of the whole history, which fixes the forgetting from slide 21. Discretization with a learned Δ turns it into a sequence model that can switch between the two views of slides 15–16. The fast kernel of slide 24 is the implementation detail that makes the convolutional mode affordable.

§5A simpler A, and the gap on language

S4 works on long signals, but two follow-ups shape everything after it. Its complicated A turns out to be unnecessary, and its time-invariance turns out to be the real limit on language.

Slide 27 / 48
slide 27 · what S4 cannot do

On the slide

S4's weaknesses on language. It treats every token the same, it cannot reason based on content because it is time-invariant, and its B does not depend on the input.

What "treats each token equally" means concretely

Look back at the kernel on slide 16. The weight on a token k positions back is CĀkB̄, a number that depends only on the distance k. Whether that token was "the" or the name of the main character, it gets the same weight at the same distance. Attention is different. The weight comes from comparing the query and the key, so it depends on what the tokens are.

A concrete case. In "Alice met Bob. … Later, Alice said hello to", predicting "Bob" needs the model to find Alice's earlier mention by its content and look next to it. A fixed kernel cannot do that, because it only knows distances. This is the gap Mamba targets (slides 31–33).

Slide 28 / 48
slide 28 · DSS and S4D

On the slide

Two follow-up papers show that the low-rank part of S4's A can be dropped. With a diagonal A, the kernel is a sum of N exponential decays, and results stay about the same if the diagonal is initialised from HiPPO.

Why diagonal makes the kernel easy

If Ā is diagonal with entries λ̄1, …, λ̄N, then Āℓ is diagonal with entries λ̄nℓ. No matrix products are needed. The kernel is

K¯ℓ= ∑n=1N CnB¯n λ¯nℓ

which is a small matrix (N × L table of powers) times a vector. That is the "about 2 lines of code".

Worked example, N = 2

Take λ̄ = (0.9, 0.5) and CnB̄n = 1 for both. Then

  • K̄0 = 1 + 1 = 2
  • K̄1 = 0.9 + 0.5 = 1.4
  • K̄2 = 0.81 + 0.25 = 1.06
  • K̄3 = 0.729 + 0.125 = 0.854

The fast-decaying dimension (0.5) covers the last few tokens and is gone by ℓ = 5 or so. The slow one (0.9) carries the longer tail. With N dimensions at different speeds, the kernel can have short-range and long-range parts at once. The values λn can be complex, which adds oscillation to the decay. That is the "(complex)" on the slide.

✦ Key takeaway

The structure of HiPPO mattered mainly as a good initialisation, not as a full matrix to keep. Diagonal A is the form every later model uses, which also makes each recurrence step cost O(N) instead of O(N2) (slide 15).

Slide 29 / 48
slide 29 · H3

On the slide

H3 ("Hungry Hungry Hippos") was built to close the gap between SSMs and attention on text. It combines two SSMs with multiplicative gates. It comes within 0.4 perplexity of a Transformer, and a hybrid that keeps two attention layers beats one.

Why multiplication helps

An LTI SSM computes a fixed weighted sum of past inputs, which is linear in the input. Multiplying two signals together, as H3's gates do, makes the output depend on products of tokens, which is a crude way of comparing them. Attention gets its power from the product of a query with a key (Lecture 5), so H3 borrows that ingredient.

The results tell two stories. Gating gets an SSM close to a Transformer on language, but not past it. And the best model keeps two attention layers, which suggests that something attention does is still missing. The callout names it. The model needs to treat tokens differently based on their content, and a time-invariant filter cannot. Mamba builds that into the SSM itself.

§6Mamba: selective state spaces

Mamba's change to the SSM is small to write down. Δ, B and C become functions of the current token. The effects are large. The model can now choose what to remember, and it can no longer be computed as a convolution.

Slide 31 / 48
slide 31 · copying, selective copying, induction heads

On the slide

Three toy tasks from the Mamba paper. Plain copying can be solved by a fixed kernel. Selective copying and induction heads need the model to look at what the tokens are.

Why the first is easy and the other two are not

  • Copying. The tokens to copy always sit at the same positions, say 1 to 4, and must come out at positions 21 to 24. A kernel that reaches back exactly 20 steps does it, whatever the tokens are. Timing alone is enough, which is what an LTI model has.
  • Selective copying. The same four coloured tokens appear at random positions among blank "noise" tokens. Now no fixed offset works. The model has to notice "this is a coloured token, store it" and "this is a blank, skip it". That decision depends on the token's content.
  • Induction heads. After "… A B … A", output "B". The model must find the earlier A by matching content and return what followed it. This is the "Alice … Bob" example from slide 27, and it is the mechanism attention-based models use for in-context copying.

These tasks are small, but they isolate the abilities language needs. Slide 41 shows Mamba's selection solving both hard ones.

Slide 32 / 48
slide 32 · selection as compression

On the slide

Attention stores everything and pays for it. A recurrent model compresses the past into a fixed state, so its quality depends on how well it compresses. Compressing well means choosing what to keep, and in Mamba the input makes that choice.

The trade-off, made concrete

Say a layer has width 2,048 and the context is 100,000 tokens. Attention's cache for that layer holds keys and values for all 100,000 tokens, which grows with every token. An SSM layer with state size 16 per channel holds 2,048 × 16 ≈ 33,000 numbers, the same at token 10 and at token 100,000. It cannot keep everything, so the only question is what it keeps.

An LTI model answers that question the same way for every token, by distance alone (slide 27). A selective model can write an important token strongly, let a filler word pass without touching the state, and wipe the state at a document boundary. The next three slides show how.

On the slide

Mamba's Algorithm 1 (S4) and Algorithm 2 (S6, the selective SSM) side by side. The only differences, shown in red, are that B, C and Δ are now computed from the input by linear projections. A stays a learned parameter.

Shape bookkeeping

Here B (in shapes) is the batch size, L the length, D the number of channels and N the state size per channel. Take batch 1, L = 4, D = 3, N = 2.

In S4 there is one Ā for the whole sequence. In S6 every token gets its own, because Āt = eΔtA and Δt comes from token t.

The price

Go back to the kernel of slide 16. It existed because the weight on an input k steps back was the same number for every output. Now the weight on x1 as seen from step 3 is C3Ā3Ā2B̄1, which involves the specific tokens in between. There is no single kernel, so the FFT trick is gone. Only the recurrence remains, and slides 36–38 are about making it fast.

⚠ Watch out

Softplus, log(1 + ez), is there to keep Δ positive. A negative step size would make Ā larger than 1 for a stable A and the state would grow. The letters also change here. From this slide on x is the input and h the state, and the B in shapes means batch size, not the matrix.

Under the hood

Slide 35 / 48
slide 35 · Mamba Figure 1

On the slide

Mamba's Figure 1. Each of the D channels carries an N-dimensional state (the orange lines). The current token is projected into Δt, Bt and Ct, which control how the state is updated and read. The state is kept in fast on-chip memory.

How big the state is

With D = 1,536 channels and N = 16, the state is 1,536 × 16 = 24,576 numbers per sequence per layer. During generation that is all the layer remembers, no matter how long the context. That is the "fixed state" entry in slide 44's table.

"Hardware-aware state expansion" refers to the problem on the next slide. The state is N times bigger than the input, and if it were written to GPU main memory at every step the layer would be very slow. The pyramid hints at the fix. Keep the expanded state in the small, fast SRAM and write only the outputs back.

§7Making the recurrence fast

Without a convolution, Mamba has to run the recurrence during training. These three slides show how it does that without being slow, by keeping the big state in fast memory and running the recurrence as a parallel scan.

Slide 36 / 48
slide 36 · the hardware-aware scan

On the slide

Running the selective recurrence naively would store every state in GPU main memory (HBM), which is too much data to move. Mamba uses three tricks from FlashAttention to avoid that. It fuses the steps into one kernel that works in SRAM, uses a parallel scan, and recomputes states during the backward pass instead of storing them.

How much memory the naive way needs

Take one sequence, L = 2,048, D = 1,536, N = 16. All the states together are 2,048 × 1,536 × 16 ≈ 50 million numbers, about 200 MB in FP32, for one layer. The input to that layer is only 2,048 × 1,536 ≈ 3 million numbers. The state tensor is N = 16 times larger than the data it is computed from.

The arithmetic is not the problem. Each state entry needs a multiply and an add, so the cost is O(BLDN), modest by GPU standards. The problem is moving data. Writing 200 MB to HBM and reading it back takes far longer than the arithmetic. This is the same diagnosis as for attention in FlashAttention. The bottleneck is memory traffic, not FLOPs.

The three tricks

  • Kernel fusion. Load x, Δ, B, C from HBM once (size BLD or BLN, not BLDN). Discretize, run the recurrence and compute y all inside SRAM. Write only y back. The 50-million-number state never touches HBM.
  • Parallel scan. Run the recurrence in O(log L) parallel steps instead of L sequential ones (next slide).
  • Recomputation. The backward pass needs the states. Recomputing them from the inputs is cheaper than storing and reloading them.
Slide 37 / 48
slide 37 · parallel scan

On the slide

A linear recurrence hk = ak hk−1 + bk can be computed in parallel. Represent each step as a pair and combine pairs with an associative operation, then reduce in a tree.

What a pair means

The pair (a, b) stands for the function "h ↦ a h + b". Doing step 1 then step 2 gives a2(a1h + b1) + b2 = (a1a2) h + (a2b1 + b2), which is the pair on the slide. Composing functions is associative, so you can group the steps however you like.

Worked example

Four steps with a = 0.5 each time and b = 1, 2, 3, 4, starting from h = 0.

Sequentially: h = 1, then 0.5·1 + 2 = 2.5, then 0.5·2.5 + 3 = 4.25, then 0.5·4.25 + 4 = 6.125.

As a tree:

  • Level 1, in parallel: (0.5, 1) ⊕ (0.5, 2) = (0.25, 0.5·1 + 2) = (0.25, 2.5), and (0.5, 3) ⊕ (0.5, 4) = (0.25, 5.5).
  • Level 2: (0.25, 2.5) ⊕ (0.25, 5.5) = (0.0625, 0.25·2.5 + 5.5) = (0.0625, 6.125).

Starting from h = 0, the final state is the second entry, 6.125, the same as the loop. The first level's left pair also gives h2 = 2.5 directly. A second pass down the tree fills in the remaining prefixes (h3) the same way. Total work stays O(L), but the number of sequential rounds drops to about log2 L, which is 11 for L = 2,048.

Under the hood

This only works because the recurrence is linear in h. With tanh(a h + b), composing two steps does not give another step of the same form, so there is nothing to combine. That is why Mamba keeps the recurrence linear and the nonlinearity outside it (slide 18). In Assignment 3 you write this scan in Triton with tl.associative_scan.

Slide 38 / 48
slide 38 · block-wise scan

On the slide

A whole long sequence does not fit in SRAM, so the scan runs in blocks. Scan each block on its own, scan the block totals to find what state enters each block, then re-scan each block from its correct starting state.

Worked example

Use the same four steps as slide 37 (a = 0.5, b = 1, 2, 3, 4), split into two blocks of two.

  1. Block scans. Each block computes its own pair as if it started from zero. Block 1 gives (0.25, 2.5). Block 2 gives (0.25, 5.5). These run in parallel.
  2. Scan over totals. Block 1 starts from 0, so it hands 2.5 to block 2. With more blocks, this step is itself a small scan.
  3. Re-scan. Block 2 restarts from 2.5: 0.5·2.5 + 3 = 4.25, then 0.5·4.25 + 4 = 6.125. Every h is now correct.

Only one block at a time needs to live in SRAM, and the blocks work in parallel. The last bullet is a reminder of the scale. This scan runs for each of the D channels and each of the N state entries, so for D = 1,536 and N = 16 there are about 24,600 independent scans per layer, which is plenty of parallel work to fill a GPU.

§8The Mamba block and its results

The selective SSM goes into one block that replaces both attention and the MLP. Then three slides of results, on toy tasks, on language modelling and on speed.

Slide 39 / 48
slide 39 · the Mamba block

On the slide

Mamba's block merges H3 and a gated MLP into one unit that is stacked uniformly, instead of alternating attention and MLP blocks.

The block, step by step

For a token vector of width D:

  1. Project up to 2D twice, giving a main branch and a gate branch.
  2. Main branch: a short causal convolution over the last few tokens (width 4 in Mamba), then SiLU, then the selective SSM.
  3. Gate branch: SiLU.
  4. Multiply the two branches elementwise, then project back down to D.

The short convolution mixes each token with its immediate neighbours before the SSM sees it, and the gate does the job of an MLP's nonlinearity. Note that the SSM runs on the 2D-wide expanded branch. That is the D in slide 33's shapes, so a model with width 768 runs 1,536 channels of SSM.

Checking the parameter count

The two input projections are D × 2D each, 4D2 together, and the output projection is 2D × D = 2D2. So one block has about 6D2 parameters (the SSM's own parameters are small by comparison). A Transformer layer has 4D2 in attention (Q, K, V, output) plus 8D2 in a 4×-wide MLP, 12D2 in total. Two Mamba blocks match one Transformer layer, which is why Mamba models have twice as many blocks as a Transformer of the same size.

Slide 40 / 48
slide 40 · the Mamba block, drawn

On the slide

The same block drawn as a picture, with the language-model head after it. Stacked Mamba blocks are followed by RMSNorm and a linear layer with softmax over the vocabulary.

What to take from it

The model around the block is an ordinary language model. Tokens are embedded, passed through many identical blocks with residual connections, normalized, and projected to next-token probabilities. Only the sequence mixer has changed. Where a Transformer uses attention, which looks back over a KV cache, Mamba uses the selective SSM, which carries a fixed state forward.

The table varies two things separately, the block architecture and the SSM layer inside it. Read it by the Layer column.

The extrapolation plot

Every model was trained on sequences of 256 tokens and then tested on longer ones. The attention models (with absolute, RoPE or xPos position encodings, see Lecture 4) fall to chance not far past the training length. Mamba stays at 100% up to 220 ≈ 1 million tokens, about 4,000 times longer than training. Its state update does not depend on position, so a longer sequence is just more steps of the same rule.

On the slide

How to read the plots

Each line shows how perplexity falls as training compute grows. Lower is better, and a line further down means the same quality for less compute. "Transformer" is the original recipe, and "Transformer++" adds the improvements from earlier lectures, RoPE (Lecture 4), SwiGLU (Lecture 8) and RMSNorm (Lecture 7). The other recurrent models (RWKV, RetNet, H3++, Hyena) sit above Transformer++. Mamba is the first attention-free model to reach it, and its lead is a bit clearer at 8,192 tokens, where longer context helps a model that can use it.

⚠ Watch out

These models are small by current standards (up to 1.3B on the plots, 3B for zero-shot). Matching a Transformer on perplexity is also not the same as matching it on every task. Exact recall of long passages is still a weakness of a fixed state (slide 44).

Slide 43 / 48
slide 43 · results on efficiency

On the slide

Speed results. The fused scan kernel beats FlashAttention-2 for sequences longer than about 2K tokens, and Mamba generates 4 to 5 times more tokens per second than a Transformer of similar size.

Why each plot looks the way it does

  • Left. Attention's cost grows like L2, so its line is the steepest on the log–log plot. The scan grows like L. At short lengths attention's well-tuned kernel wins, but past 2K the scan is faster, and the gap widens with length. The naive PyTorch scan is linear too, but it moves all the states through HBM (slide 36), so it is far slower and runs out of memory.
  • Right. A Transformer must keep a KV cache for every sequence in the batch, and that cache grows with length. The GPU fills up, so batch size is capped. Mamba keeps only a fixed-size state per sequence, so it fits much larger batches, and throughput (tokens per second across the batch) keeps rising with batch size.

The DNA and audio bullet is a reminder that SSMs began as models for long signals (slide 25). Those domains have very long sequences where attention's cost is the main obstacle.

§9Comparison and takeaways

The deck closes with a table that places Transformers, S4, Mamba and Mamba-2 side by side, a list of takeaways, and reading material.

Slide 44 / 48
slide 44 · the four models compared

On the slide

The whole lecture in one table, comparing Transformers, S4, Mamba and Mamba-2 on training cost, generation cost, content selection, state size and exact recall.

The story the table tells

  • Transformer to S4. S4 gains cheap training (L log L) and constant-cost generation, but loses content selection and recall. Every token is weighted by distance alone.
  • S4 to Mamba. Mamba gets selection back by making Δ, B, C depend on the input. It loses the convolution and trains with a scan, which is still linear in L.
  • Mamba to Mamba-2. The deck does not cover Mamba-2 in its own slides. The table says enough to place it. It makes A a single number per head (a "scalar decay") instead of a diagonal. That restriction lets the scan be rewritten as ordinary matrix multiplications over chunks of the sequence, which GPUs run very fast. The state can then be much bigger, 64 to 256 per head instead of 16 per channel.

The last row is the honest one. No row other than the Transformer says "strong" for exact recall. A fixed state is a compression of the past (slide 32), and a bigger state, as in Mamba-2, helps but does not remove the limit.

Slide 45 / 48
slide 45 · key takeaways

On the slide

Five takeaways, one per part of the lecture plus one on where the field stands.

The two that need unpacking

Takeaway 4. Linear attention, from the previous lecture, keeps a state that is a running sum of k⊤v outer products. An SSM whose decay Āt is a single number per step does almost the same thing. It adds Bt times xt to a state that is shrunk by Āt each step, and reads it with Ct. Match C to the query, B to the key and x to the value, and the SSM is linear attention where older tokens are down-weighted by the product of the decays since then. That is "masked linear attention". It is why Mamba-2 can be computed with matrix multiplications in chunks.

Takeaway 5. The H3 result on slide 29 (a few attention layers help) turned out to be the practical answer. Several production models since 2025, listed on slide 48, mix many Mamba-style layers with a few attention layers. The SSM layers keep the cost and memory low, and the attention layers handle exact recall. The deck lists the open problems without going into them, so for this course it is enough to know that recall and state tracking are where pure SSMs still fall short.

Zoom out. An SSM is a linear recurrence obtained by sampling a continuous system every Δ time units. Because it is linear and, in S4, the same at every step, it can be trained as one long convolution and run at generation time as an RNN with a fixed state and no KV cache. A random A forgets, so HiPPO chooses one whose state is the best polynomial summary of the history, and S4 computes the resulting kernel fast. S4D then showed that a diagonal A is enough. On language these models fall short because they weight tokens by distance, not content. Mamba fixes that by computing Δ, B and C from each token, which turns Δ into a gate that can keep the state or overwrite it. The cost is losing the convolution, and Mamba pays it with a parallel scan that keeps the large state in SRAM. For an exam, be able to discretize a one-dimensional SSM, compute a short kernel and check it against the recurrence, explain why selection breaks the convolution, and show that Δ acts as a gate.

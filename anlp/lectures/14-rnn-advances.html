Lecture 14 · 41 slides

RNN advances: train like a Transformer, decode like an RNN.

Every token a Transformer generates has to look at the keys and values of every earlier token, so the KV cache and the cost per token both grow with the context. An RNN keeps a fixed-size state instead. This lecture explains why classic RNNs lost anyway, the one change (making the recurrence linear in the state) that lets them train in parallel again, and how RetNet, RWKV, Griffin, xLSTM, GLA and DeltaNet all turn out to be the same matrix-valued memory with different update rules. It ends with what a fixed state cannot do, and why the models shipping in 2025 and 2026 mix a few attention layers back in.

Lecture 14 41 slides Manish Shrivastava · Aparajitha Allamraju

§0The deck at a glance

This is the first of three lectures on alternatives to attention. The next two cover state space models and diffusion language models. Slides 1–4 make the case for recurrence by counting KV-cache memory. Slides 5–6 recap the LSTM and GRU and list why they lost to Transformers. Slides 7–10 give the key trick: if the gates depend only on the current input and not on the previous state, the recurrence becomes linear and can be computed for all positions at once. Slides 11–25 tour the model families in roughly historical order, from QRNN (2016) through RetNet, RWKV, LRU, Griffin, xLSTM and minGRU to gated linear attention and DeltaNet. Slides 26–27 put them all in one table. Slides 28–30 cover test-time training, where the state is itself a small model. Slides 31–33 show what a fixed-size state cannot do well, and slides 34–38 show the hybrids that are used in practice. Slides 39–41 summarise and point to the next lecture.

One equation carries most of the lecture. The state is a matrix St, the model writes to it with an outer product vtkt⊤ and reads from it by multiplying with a query, ot = Stqt. The models differ only in what they do to the old state before writing, which is the matrix Mt in St = St−1Mt + vtkt⊤. If you can say what Mt is for each model, and why the richer choices remember better, you understand the lecture.

§1Why RNNs again

Transformers train well. The problem is generation, where the KV cache grows with every token. Long contexts and long reasoning traces made that cost too big to ignore.

Slide 01 / 41
slide 01 · title

On the slide

Current RNN Advances, taught by Manish Shrivastava and Aparajitha Allamraju. The title slide is dated October 19, 2026.

Where this fits

Lecture 2 explained that Transformers replaced RNNs because attention lets every position be computed at once during training. This lecture asks whether that trade was necessary. Most of the answer is that RNNs can be trained in parallel too, provided their update is built the right way.

Slide 03 / 41
slide 03 · the KV cache grows, an RNN state does not

On the slide

Attention costs O(T) compute and O(T) memory for each generated token, while an RNN costs O(1) for both. The price is that the RNN only keeps a compressed summary of the past.

Checking the KV-cache arithmetic

For every token, every layer stores one key vector and one value vector of size d. In FP16 each number takes 2 bytes. For Llama-2-7B that gives

2 (K and V) × 32 layers × 4096 × 2 bytes = 524,288 bytes = 0.5 MiB per token.

At 32K tokens that is 32,768 × 0.5 MiB = 16 GiB, and at 128K it is 64 GiB, for a single sequence. The weights themselves are only about 13.5 GB. Serve a few users with long contexts and the cache, not the model, decides how many fit on a GPU.

What a fixed state costs, for comparison

Take a recurrent model with the same shape (32 layers, d = 4096) that splits each layer into 32 heads of size 128 and keeps a 128 × 128 matrix state per head. Each layer then stores 32 × 128 × 128 = 524,288 numbers, which is 1 MiB in FP16, and the whole model stores 32 MiB. That is the same as the KV cache of just 64 tokens, and it stays at 32 MiB whether the context is 1K or 1M tokens.

✦ Key takeaway

The last row of the table is the whole trade-off. Attention keeps every past token exactly, so it can always look back. A recurrent model has to decide what to squeeze into a fixed budget. The rest of the lecture is about making that squeeze as smart as possible, and slides 31–33 show where it still falls short.

Slide 04 / 41
slide 04 · the "impossible triangle"

On the slide

There are three things you want. Training should be parallel, inference cheap and quality strong. Each older architecture gets two of the three, and the RetNet paper drew this as an "impossible" triangle with its own model in the middle.

Reading the triangle

  • A Transformer computes all positions of a training sequence at once and is strong, but decoding grows with context (slide 3).
  • An LSTM decodes in O(1) and was strong for its time, but training must walk through the sequence one step at a time (slide 6).
  • Linear attention (Lecture 6) trains in parallel and decodes in O(1), but its quality was clearly below softmax attention.

Every model in slides 11–25 is an attempt to sit in the middle. The approach shared by all of them is to start from the linear-attention corner, which already has two of the three properties, and improve the quality.

§2Why classic RNNs lost

A short recap of the LSTM and GRU, and the three problems that let Transformers replace them. The first problem turns out to be the important one.

Slide 05 / 41
slide 05 · Elman, LSTM, GRU

On the slide

The three classic recurrent cells. The orange Uht−1 term in the LSTM gates is the one to watch, because it is what forces each step to wait for the previous one.

What the gates do

The LSTM cell update ct = ft ⊙ ct−1 + it ⊙ c̃t is a weighted blend. The forget gate ft (between 0 and 1) decides how much old memory to keep, and the input gate it decides how much of the new candidate c̃t to add. The GRU does the same with one gate, zt for "new" and 1 − zt for "old". Because the old memory is carried forward by multiplying with a gate close to 1 rather than by passing through a tanh and a weight matrix, information can survive many steps.

Hold on to the shape of these updates, (gate) ⊙ (old state) + (something new). Almost every model in this lecture keeps that shape. What changes is what the gate is allowed to depend on.

Slide 06 / 41
slide 06 · three problems

On the slide

Classic RNNs had three weaknesses. Training is sequential, gradients vanish or explode through long products, and the whole past has to fit in one vector. Modern RNNs fix the first two, then the third.

Problem 1 in numbers

A GPU is fast because it does thousands of multiplications at the same time. Training a Transformer on a 4096-token sequence is a handful of large matrix multiplications over all 4096 positions. An LSTM has to run 4096 small steps one after another, because step t needs ht−1 before it can even compute its gates. Most of the GPU sits idle during each of those small steps.

Problem 2 in numbers

The gradient from step 100 back to step 1 is a product of 99 Jacobians. If each one shrinks a vector by a factor of 0.9, the product shrinks it by 0.9100 ≈ 2.7 × 10−5 (rounding 99 to 100). If each one grows it by 1.1, the product is 1.1100 ≈ 13,780. Neither gives a usable training signal. LSTM gating helps but doesn't remove the problem.

Problem 3

An LSTM with d = 1024 has 1024 numbers of state per layer. Compare that with the 32 MiB matrix state from slide 3. A vector state is simply too small to hold many facts, and slide 10 shows how a matrix state fixes this.

§3The linear-recurrence trick

Make the gates depend only on the current input. The recurrence then becomes linear in the state, which makes it associative, which means a GPU can compute it in parallel. Linear attention from Lecture 6 already has this form.

Slide 07 / 41
slide 07 · gates from the input only

On the slide

Remove ht−1 from inside the gates. The update becomes ht = at ⊙ ht−1 + bt, where at and bt come from xt alone.

ht= at⊙ht−1 +bt ⟹ ht= ∑s=1t ( ∏r=s+1t ar) ⊙bs

Why this one change matters

In an LSTM you can't compute f2 until you have h1. Here at = σ(Wxt) needs only the input, and the inputs are all known at training time. So all the at and bt for a whole sequence come out of one matrix multiplication over a T × d input. What remains is the cheap elementwise recurrence, and slide 8 shows that even that can be parallelised.

A three-step example

Use scalars with h0 = 0, a = (0.9, 0.5, 0.8) and b = (1, 2, 3).

  • Step by step, h1 = 1, then h2 = 0.5 × 1 + 2 = 2.5, then h3 = 0.8 × 2.5 + 3 = 5.
  • With the unrolled formula, h3 = (a2a3) · b1 + a3 · b2 + b3 = 0.4 × 1 + 0.8 × 2 + 3 = 5.

The unrolled form shows what a means. Input b1 reaches step 3 scaled by every gate after it, 0.5 × 0.8 = 0.4. A gate near 1 lets old information pass, and a gate near 0 wipes it out. That is a forget gate, and since it's chosen per token from the input, the model can decide which tokens should trigger forgetting.

⚠ Watch out

"Linear" means linear in h. The gates are still nonlinear functions of xt, and the MLP between layers adds the rest of the nonlinearity. What is lost is the ability of a single layer to let its gates react to what it has already stored. Slide 27 comes back to this as "state tracking".

Slide 08 / 41
slide 08 · parallel scan

On the slide

Treat each step as a pair (at, bt) and define a way to combine two pairs. The combine operation is associative, so the whole sequence can be combined like a prefix sum, in about log2 T rounds.

Where the combine rule comes from

Each step is the function h ↦ ath + bt. Apply step 1 and then step 2 and you get a2(a1h + b1) + b2 = (a2a1)h + (a2b1 + b2). That is again of the form "multiply, then add", with the pair (a2a1, a2b1 + b2). Composing functions is always associative, so it doesn't matter how you group the steps.

Check it on slide 7's numbers

  • Left to right, (0.9, 1) • (0.5, 2) = (0.45, 2.5), and then (0.45, 2.5) • (0.8, 3) = (0.36, 0.8 × 2.5 + 3) = (0.36, 5).
  • Right first, (0.5, 2) • (0.8, 3) = (0.4, 4.6), and then (0.9, 1) • (0.4, 4.6) = (0.36, 0.4 × 1 + 4.6) = (0.36, 5).

Both groupings give h3 = 5 (the second number, since h0 = 0). Because grouping is free, the GPU can combine neighbours in parallel. In the diagram, round 1 combines each position with the one before it, round 2 with the result two back, and round 3 with the result four back. After 3 rounds every ht for 8 positions is done. For T = 4096 that is 12 rounds instead of 4096 steps.

⚠ Watch out

The scan drawn on the slide (Hillis–Steele) is the simplest to picture, but it does more total work than a plain loop. Count the orange edges and you get 7 + 6 + 4 = 17 combines for 8 positions, and in general about T log T. The "O(T) work" bullet refers to Blelloch's version, which takes about twice as many rounds but only O(T) combines. Both have O(log T) depth, which is what matters for speed.

Slide 09 / 41
slide 09 · recurrent, parallel, chunkwise

On the slide

A linear recurrent layer can be computed three ways that give identical outputs. Decoding uses the recurrent form, and training uses the parallel or the chunkwise form.

The three forms

  • Recurrent. Update the state once per token. This is ideal for generation, where tokens arrive one at a time anyway.
  • Parallel. Write the output as attention without the softmax, (QK⊤ ⊙ D)V, where D is a lower-triangular mask that also holds the decay factors (slide 12 gives an example). It is all matmuls, but it builds a T × T matrix, so it is only good for short sequences.
  • Chunkwise. Cut the sequence into chunks of, say, 64 tokens. Inside each chunk use the parallel form, which only needs a 64 × 64 matrix. Between chunks, pass the state along with the recurrent form.

Why chunkwise wins for training

For T = 4096 and chunks of 64, there are 64 chunks. The sequential part is now 64 state hand-offs instead of 4096, and the work inside each chunk is small dense matrix multiplication, which is what GPU tensor cores are fast at. The quadratic cost is only 642 per chunk, so total cost grows linearly with T. Libraries such as flash-linear-attention implement this form for most of the models in this lecture.

Slide 10 / 41
slide 10 · linear attention as an RNN

On the slide

Linear attention from Lecture 6 is already a linear RNN. Its state is a dv × dk matrix that adds one outer product per token. It never forgets anything, and that is its main flaw.

From attention to a running sum

Softmax attention can't be split into a running sum because exp(q⊤k) mixes q and k together. With a kernel φ(q)⊤φ(k) the query factors out of the sum over past tokens:

Σs≤t vs (φ(ks)⊤φ(qt)) = (Σs≤t vsφ(ks)⊤) φ(qt) = St φ(qt).

The bracket doesn't depend on the query, so it can be kept as a running total St. That is ht = atht−1 + bt with at = 1 and bt = vtφ(kt)⊤. From here on the deck drops the φ and writes k and q directly.

The state as a key → value memory

Shapes first. vt is dv × 1 and kt is dk × 1, so vtkt⊤ is dv × dk, and Stqt is a dv-vector. Now a tiny example with dk = dv = 2. Store k1 = (1, 0) → v1 = (3, 5) and k2 = (0, 1) → v2 = (−1, 2).

S = v1k1⊤ + v2k2⊤ = [[3, −1], [5, 2]]

Query with q = k1 = (1, 0) and you get the first column, Sq = (3, 5) = v1. The memory returns the value stored under that key. Querying with k2 returns (−1, 2).

"Never forgets", in the same example

Suppose a later token says key k1 should now map to (7, 7). Linear attention adds (7, 7)k1⊤, so querying k1 returns (3, 5) + (7, 7) = (10, 12), which is a mix of the old and new values, not the new one. Nothing ever leaves the state. The fixes come in two kinds. Decay shrinks old entries (slides 12–24), and the delta rule overwrites the value for a specific key (slide 25).

✦ Key takeaway

A matrix state of size dv × dk is what solves problem 3 from slide 6. With dk = dv = 128 it holds 16,384 numbers per head, not 128.

§4QRNN, RetNet and RWKV

The first wave. QRNN showed the linear-recurrence idea in 2016. RetNet and RWKV took linear attention, added decay so the state forgets, and scaled it to billions of parameters.

Slide 11 / 41
slide 11 · timeline

On the slide

Ten years of models, grouped by year. The question people asked changed from "can RNNs match Transformers?" (2023) to "which update rule?" (2024) to "which hybrid should we ship?" (2025–26).

How to use this slide

You don't need the dates. Use it as a map of the rest of the lecture. The 2023 column mostly adds decay to linear attention, the 2024 column makes the decay depend on the data and adds the delta rule, and the 2025–26 column is about mixing these layers with attention in large production models. State space models such as Mamba belong on the same timeline but are covered in Lecture 15.

Slide 12 / 41
slide 12 · QRNN and SRU

On the slide

QRNN computed its gates and candidate values with convolutions over the input, so only a cheap elementwise update stayed sequential. It ran up to 16× faster than an LSTM. SRU did the same with matrix multiplications.

Spot the pattern

The QRNN update is slide 7's form with at = ft and bt = (1 − ft) ⊙ zt. Since ft and zt come from a convolution over a few neighbouring inputs, never from ct−1, the expensive part runs in parallel. The idea was there in 2016. What was missing was a big state (QRNN's state is a vector, so problem 3 from slide 6 remains), training at scale, and GPU kernels like the chunkwise form.

Slide 13 / 41
slide 13 · RetNet retention

On the slide

RetNet is linear attention with one change. Before each write, the state is multiplied by a constant γ between 0 and 1, so old entries fade. Each head has its own γ.

Why the two forms agree

Unroll the recurrence. A write made at step m is multiplied by γ once for every later step, so at step n it has been scaled by γn−m:

on = Σm≤n γn−m (qn⊤km) vm

That is exactly the parallel form. QK⊤ gives the qn · km scores, and D zeros out the future (causal mask) and applies the decay. For 3 tokens with γ = 0.5,

D = [[1, 0, 0], [0.5, 1, 0], [0.25, 0.5, 1]].

Compare this with a Transformer, where the causal mask is 0 or −∞ inside a softmax. Here there is no softmax and the mask has real-valued weights.

Multi-scale: what γ means

A decay of γ keeps information for roughly 1/(1 − γ) tokens. γ = 0.9 remembers about 10 tokens, γ = 0.99 about 100 and γ = 0.999 about 1000. Giving each head a different γ lets some heads track local syntax and others longer-range context. It works a bit like the different frequencies in sinusoidal position encodings (Lecture 4), and the xPos-style rotation RetNet adds is a relative position encoding in the same family as RoPE.

⚠ Watch out

γ is a fixed number per head, learned or set once and the same for every token. A sentence boundary, a new document or an important name all get forgotten at the same rate. That is the weakness the next models attack.

Slide 14 / 41
slide 14 · RetNet inference numbers

On the slide

The RetNet authors' 7B model at 8K input used 3.4× less GPU memory, had 8.4× the throughput and 15.6× lower latency than a Transformer of the same size.

Where the gains come from

All three numbers follow from slide 3. With no KV cache, memory per sequence is fixed, so more sequences fit in a batch (throughput), and each new token does a fixed amount of work instead of reading 8K cached keys (latency). The gap grows with input length. These are the authors' own numbers, and the slide warns that later work found fixed decay weaker on quality than the data-dependent gating of GLA and Mamba-2.

Slide 15 / 41
slide 15 · RWKV-4 time-mix

On the slide

RWKV-4 replaces attention with a "time-mix" that, for each channel, takes a weighted average of past values. The weights decay exponentially with distance. A separate bonus u applies to the current token, and a sigmoid gate (the receptance r) scales the output.

Read it as a softmax with a recency penalty

Each past value vi gets weight exp(ki − (t−1−i)w), and the weights are normalised by their sum. So it is a softmax over past tokens with score ki − (distance) × w. Unlike attention, the score has no query in it. How much token i counts depends on its own key and its age, not on what the current token is looking for. The receptance σ(rt) is the only current-token control, and it just scales the result per channel.

A small example

One channel, at t = 3, with w = ln 2 (each step halves the weight), all keys 0, u = 0 and values v1 = 1, v2 = 3, v3 = 5. The weights are e−ln 2 = 0.5 for token 1 (one step old), e0 = 1 for token 2 and eu+k3 = 1 for the current token, so

wkv3 = (0.5 × 1 + 1 × 3 + 1 × 5) / (0.5 + 1 + 1) = 8.5 / 2.5 = 3.4.

Why it is an RNN

Call the numerator sum (including token t with no bonus) At. Every older term gains one more factor of e−w per step, so At = e−wAt−1 + ektvt, which is slide 7's form again. The denominator works the same way. RWKV-4 keeps a numerator and a denominator per channel as its state, so its state is still a vector, and RWKV-5 changes that.

Token shift is a cheap trick. Before computing r, k and v, each token's input is blended with the previous token's input, which gives every layer a direct look at the immediately preceding token.

Slide 16 / 41
slide 16 · RWKV-5, 6 and 7

On the slide

Three versions, three steps forward. RWKV-5 moves to a matrix state with a fixed decay per key channel. RWKV-6 lets the decay depend on the current token. RWKV-7 adds a delta-rule term that removes old content before writing new content.

What multiplying by diag(w) on the right does

S diag(w) scales column j of S by wj. Column j holds whatever was written under key dimension j, so each key dimension forgets at its own rate. RetNet used one scalar γ for the whole head. RWKV-5 uses a vector, and RWKV-6 lets that vector change with each token (wt). A token like "." can then push some channels' decay toward 0 to clear them, while other tokens keep the decay near 1.

RWKV-7 as a delta rule

Set the decay to 1 and the learning rate to a scalar β, and the RWKV-7 transition becomes I − βκ̂κ̂⊤. That is DeltaNet's transition from slide 25. Multiplying by it removes the part of the state stored along the key direction κ̂ before the new value is written. RWKV-7 generalises it with a per-channel decay and a per-channel learning rate at. Slide 27 explains why this extra structure lets it "track state".

Slide 17 / 41
slide 17 · RWKV-7 block

On the slide

An RWKV-7 block looks like a pre-norm Transformer block with the attention sublayer replaced by Time Mix. The state is a 64 × 64 matrix per head.

The general design pattern

This is how almost every model in the lecture is built. A Transformer block has two parts, a token mixer (attention, which moves information between positions) and a channel mixer (the MLP from Lecture 8, which works on each position separately). Modern RNNs keep the residual stream, the norms (Lecture 7) and the MLP, and replace only the token mixer. Time Mix computes six per-token vectors from the shifted input, r, w, k, v, a and a gate g, and the WKV7 kernel applies the slide 16 update to the state.

A 64 × 64 state per head is 4,096 numbers. Whatever the context length, the memory and work for each new token stay the same.

§5LRU, Griffin, xLSTM and minGRU

Four more routes to the same place. LRU strips a classic RNN down to see which parts matter. Griffin adds gating and local attention. xLSTM and minGRU start from the LSTM and GRU and end up at a linear recurrence anyway.

Slide 18 / 41
slide 18 · LRU, four ingredients

On the slide

Start from a plain tanh RNN and make four changes, one at a time. The result, the Linear Recurrent Unit, reaches the level of S4 and S5 on Long Range Arena. The plot shows accuracy climbing with each change.

The four steps

  1. Linearise. Remove the tanh, so xk = Axk−1 + Buk. This makes slide 8's parallel scan possible.
  2. Diagonalise. A dense matrix A can almost always be written as PΛP−1 with Λ diagonal, if complex numbers are allowed. Absorb P into the input and output projections and the recurrence becomes elementwise, xk = λ ⊙ xk−1 + ..., which is cheap. A complex λ = |λ| eiθ both shrinks (|λ|) and rotates (θ), so each channel can hold a decaying oscillation.
  3. Stable parameterisation. The model learns ν and sets |λ| = exp(−exp(ν)). Whatever value ν takes, exp(ν) > 0, so |λ| is always strictly between 0 and 1 and the state can't blow up. Initialising |λ| close to 1 (the "ring init" on a ring near the unit circle) gives long memory from the start.
  4. Normalise with γ. When |λ| is close to 1, inputs pile up. For unit-variance random inputs the state's variance settles at 1/(1 − |λ|2), which is about 50 for |λ| = 0.99. Multiplying the input by γ = (1 − |λ|2)1/2 brings that back to 1.
→ Next lecture

S4 reaches a very similar diagonal linear recurrence by starting from continuous-time differential equations. LRU's point is that you don't need that theory to get the result. Lecture 15 tells the same story from the SSM side.

Slide 19 / 41
slide 19 · RG-LRU, Hawk and Griffin

On the slide

DeepMind's RG-LRU is a real-valued diagonal LRU with two input-dependent gates. Hawk stacks only RG-LRU blocks. Griffin uses two RG-LRU blocks for every local-attention block with a 1024-token window.

How the gate controls the decay

The base decay a = σ(Λ) is learned per channel. The recurrence gate rt ∈ (0, 1) raises it to a power, at = a8rt. Take a channel with a = 0.9.

  • rt → 0 gives at → 1, and the input factor √(1 − at2) → 0. The state is kept and the token is ignored.
  • rt = 0.5 gives at = 0.94 ≈ 0.656 and an input factor of about 0.755.
  • rt = 1 gives at = 0.98 ≈ 0.430 and an input factor of about 0.903. Old state fades fast and the new token mostly replaces it.

So each token decides, through rt, whether it is worth remembering. That is data-dependent decay, the missing piece from RetNet. The √(1 − at2) factor is the same normaliser as LRU's γ, and it keeps the state's size steady whatever the gate does.

Why mix in local attention

Local attention with a 1024-token window is exact for nearby tokens and its KV cache stops growing at 1024 entries. The recurrent layers carry information further back in compressed form. Griffin's recurrent block also has a short convolution over the last few tokens, which plays the same role as RWKV's token shift.

Slide 20 / 41
slide 20 · Griffin results

On the slide

The loss curves show Griffin scaling like a Transformer with multi-query attention (MQA). The throughput chart shows decoding speed at 1B parameters. Griffin was released as RecurrentGemma.

Reading the throughput chart

The MQA bars shrink as the number of decoded tokens grows, because each new token has to read a longer KV cache. Hawk's bars stay flat, since its per-token cost doesn't depend on length. Griffin sits in between. Its local attention has a capped cache, so its bars flatten too, at a lower level than Hawk because a third of its layers are attention. By 4096 tokens Hawk is 14.8× faster than MQA and Griffin 6.6×. These are the slide 3 arguments showing up in measurements.

Slide 21 / 41
slide 21 · xLSTM: sLSTM and mLSTM

On the slide

The group behind the original LSTM updated it in two ways. sLSTM keeps a vector state and mixes memory across steps, so it stays sequential. mLSTM switches to a matrix memory with exponential input gates and can be trained in parallel.

mLSTM is linear attention with gates

The mLSTM update Ct = ftCt−1 + itvtkt⊤ is slide 10's key → value memory with a scalar forget gate ft on the old state and a scalar input gate it on the new write. The read-out divides by a normaliser nt = ftnt−1 + itkt, which plays the same role as linear attention's denominator zt. The max with 1 stops the division from blowing up when nt⊤qt is near 0.

Why an exponential input gate

A sigmoid gate is at most 1. With it = exp(ĩt) the gate can be 10 or 100, so one important token can write strongly enough to outweigh everything already stored. This is what "memories can be strongly revised" means. Exponentials overflow easily, so xLSTM also tracks a running maximum (the stabiliser) and works with the gates relative to it, the same trick used to compute softmax safely.

Slide 22 / 41
slide 22 · xLSTM 7B

On the slide

xLSTM 7B is a 7B model built only from mLSTM blocks. Its authors report quality comparable to similar-size models and faster inference than Llama- and Mamba-based 7B models.

Why decode speed became the selling point

Reasoning models write thousands of tokens of chain-of-thought before answering, so the cost of a query is mostly the cost of generating tokens. That is the O(T)-per-token part of slide 3, and it is where a fixed state helps most. The boxed remark is the main lesson. An LSTM group and a linear-attention group arrived at the same update from opposite ends.

Slide 23 / 41
slide 23 · minGRU and minLSTM

On the slide

Take a GRU, remove ht−1 from the gate and the candidate, and drop the tanh. What is left is a linear recurrence that trains with a parallel scan, 175× to 1361× faster per step than the original.

Match it to slide 7

minGRU is ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t with zt and h̃t computed from xt alone. So at = 1 − zt and bt = zt ⊙ h̃t. Nothing else is needed.

Why the speed-up grows with length

The original GRU needs T sequential steps and the scan needs about log2 T rounds. Going from 512 to 4096 tokens multiplies the GRU's steps by 8 but adds only 3 rounds to the scan, which is why the speed-up jumps from 175× to 1324×. The point of the paper's title is that the gains in this lecture come mostly from linear-in-state recurrence and parallel training, not from any one clever architecture.

§6Data-dependent decay and the delta rule

Two upgrades to linear attention's update. A forget gate that depends on the current token lets the model erase quickly. The delta rule lets it overwrite one key's value without disturbing the others.

Slide 24 / 41
slide 24 · GLA, HGRN, HGRN2

On the slide

Gated linear attention gives every key dimension a forget rate αt computed from the current token. HGRN adds a floor on the forget gate that rises with depth, and HGRN2 enlarges the state with an outer product. The slide calls data-dependent decay the biggest single quality jump over fixed decay.

Fixed versus content-aware decay

Under RetNet's fixed γ = 0.9, a name seen 50 tokens ago has been scaled by 0.950 ≈ 0.005 whatever happened in between. Under GLA, the tokens in between choose their own α. Filler words can set α near 1 so the name survives, and a token that starts a new topic can set α near 0 to clear the old content. GLA's update is the same as RWKV-6's from slide 16, and it is the "data-dependent diagonal" row in the table on slide 26.

HGRN's rising floor

If the forget gate is forced to be at least some value, the layer can't forget faster than that floor allows. HGRN learns a floor that is low in the bottom layers and high in the top layers, so lower layers handle local patterns and upper layers keep long-range information. It's the same idea as RetNet's multi-scale heads, spread across depth instead of across heads.

Why GLA's kernel matters

FlashLinearAttention is the chunkwise form from slide 9, written to keep data in fast on-chip memory as much as possible. Without a fast kernel, a linear-time layer can still be slower than softmax attention in practice, because GPUs reward large matrix multiplications over many small elementwise steps.

Slide 25 / 41
slide 25 · DeltaNet and Gated DeltaNet

On the slide

DeltaNet first asks the memory what it currently returns for key kt, then writes only the difference between the target vt and that prediction. Gated DeltaNet adds a forget gate on top.

St= St−1+ βt (vt− St−1kt) kt⊤ = St−1 (I−βt ktkt⊤) +βtvtkt⊤

Back to slide 10's example

The memory is S = [[3, −1], [5, 2]], holding (1, 0) → (3, 5) and (0, 1) → (−1, 2). We want k1 = (1, 0) to map to (7, 7) instead. Take β = 1.

  • Read the prediction, Sk1 = (3, 5).
  • Error = target − prediction = (7, 7) − (3, 5) = (4, 2).
  • Write the error, S + (4, 2)k1⊤ = [[7, −1], [7, 2]].

Now Sk1 = (7, 7), the new value exactly, and Sk2 is still (−1, 2). Plain linear attention gave (10, 12) here. The delta rule replaced one entry and left the other untouched. With β between 0 and 1 it moves only part of the way toward the target.

Why it is a gradient step

Measure how wrong the memory is for this key with L(S) = ½‖Skt − vt‖2. Its gradient is (Skt − vt)kt⊤, and one step of gradient descent with learning rate βt gives exactly the update above. Each token trains the memory a little on its own key–value pair. Slide 28 takes this idea further.

Gating and delta do different jobs

The forget gate αt scales the whole state down, which is a fast way to clear everything when the context changes. The delta term edits one key direction and leaves the rest alone. Gated DeltaNet uses both, and it is the recurrent layer in Qwen3-Next and Qwen3.5 (slide 36).

→ See also

Assignment 3 implements DeltaNet. A3 §4 works through the same update with tensor shapes, and the slide's "Householder (WY) representation" is the trick its chunkwise kernel uses to batch many I − βkk⊤ factors into matrix multiplications.

§7One table for all of them

Every model so far fits one update, St = St−1Mt + writet. What separates them is how much structure the transition matrix Mt has.

Slide 26 / 41
slide 26 · the unifying table

On the slide

Eight models in one table, each defined by its transition Mt and its write term. The rows go from the simplest transition (identity) to the richest (diagonal plus rank-1).

How to read Mt

Right-multiplying the old state by Mt is what the layer does to its memory before writing. Each step up the table gives the model finer control over what to forget.

  • Identity. Keep everything (linear attention).
  • Scalar. Shrink the whole memory by one number. The number is fixed in RetNet and chosen by the token in Mamba-2 and mLSTM.
  • Diagonal. Shrink each key dimension by its own amount (GLA, RWKV-6).
  • Identity + rank-1. Remove what is stored along one key direction and leave the rest (DeltaNet). Gated DeltaNet multiplies this by a scalar decay, and RWKV-7 combines it with a diagonal.

Why not just use a full matrix?

A general dk × dk transition per token would cost dk3 operations to apply to the state and would have to be stored for every token during training. Diagonal and rank-1 matrices can be applied in dk2 work and fit the chunkwise kernels of slide 9. The table is a list of the cheapest structures that still give useful control. That is the cost the box refers to.

✦ Key takeaway

Mamba-2 appears in this table as "linear attention with a data-dependent scalar decay". Lecture 15 derives the same thing from state space models.

Slide 27 / 41
slide 27 · LS, FD, DD, GE

On the slide

The RWKV-7 paper compares update rules on four properties. Large state, flexible (per-dimension) decay, decay that depends on the input, and transition eigenvalues allowed outside [0, 1]. The paper writes vectors as rows, so its v⊤k is our vk⊤.

The first three you already know

LS is slide 10's matrix state, FD is the diagonal row of slide 26 and DD is data-dependent decay from slide 24. The new one is GE.

What GE buys, with parity

Suppose the task is to read a bit string and say whether it has an odd number of 1s. A recurrent model can do it with one number. Start at +1 and flip the sign on every 1, so the state is multiplied by −1 on a 1 and by +1 on a 0. Flipping a sign needs a transition with eigenvalue −1. A decay between 0 and 1 can only shrink the state, never flip it, so no setting of the gates in GLA or Mamba can do this in one layer.

The delta-rule transition I − βkk⊤ (with ‖k‖ = 1) has eigenvalue 1 − β along k and 1 elsewhere. With β allowed up to 2, that eigenvalue reaches −1, and the transition becomes a reflection. This is the sense in which RWKV-7 "tracks state" and can recognise all regular languages (slide 16). Tracking whose turn it is in a game or which variable holds which value in code needs the same ability.

⚠ Watch out

This is the loss slide 7 warned about. Dropping ht−1 from the gates removed the classic RNN's way of doing state tracking. Richer transitions are how linear RNNs get some of it back while staying parallel.

§8Test-time training: the state as a model

The delta rule is one gradient step on a linear memory. Test-time training makes that the definition. The state is the weights of a small model, and each token trains it.

Slide 28 / 41
slide 28 · TTT layers

On the slide

Any sequence layer can be described by three things, a state, an update rule and an output rule. For a classic RNN the state is a vector. For attention it is the list of all past keys and values. For TTT it is the weights W of a small model f, updated by one gradient step per token.

The three rows side by side

Attention's "update" is to append, which is why its cost per token is O(t). The RNN and TTT rows both cost O(1) because their state has a fixed size. In TTT the loss ℓ is self-supervised. The token is projected to a "key" view and a "value" view, and f is trained to reconstruct the value from the key, much like slide 25's ½‖Sk − v‖2.

Connecting to DeltaNet

If f is linear, f(k; W) = Wk, and the loss is ½‖Wk − v‖2, one gradient step is W ← W − η(Wk − v)k⊤, which is the delta rule. TTT-Linear lives very close to DeltaNet. TTT-MLP replaces the matrix with a two-layer MLP, so the memory can store a nonlinear map from keys to values, at the cost of more computation per token.

Slide 29 / 41
slide 29 · perplexity by position

On the slide

Perplexity at each position of a 32K-token document, averaged over many documents. A model that uses its context well should keep getting better further into the document.

How to read the plot

Token 20,000 has seen 20,000 tokens of context, so it should be easier to predict than token 200. The Transformer's curve keeps going down because it can look back at everything. Mamba's flattens after about 16K, meaning the extra context no longer helps because its state is full. TTT's curves keep falling like the Transformer's. The box is the summary. A recurrent layer has two limits, how much its state holds and how well its update decides what to keep.

Slide 30 / 41
slide 30 · research directions

On the slide

Four 2025 directions, each extending the "update = learning step" idea in a different way.

One line on each

  • Titans uses a neural memory trained at test time for the long term and attention for the short term, like a hybrid where the recurrent part is a TTT-style learner.
  • ATLAS fits the memory to a window of recent tokens instead of just the newest one, which is like taking a gradient step on a small batch instead of a single example.
  • DeltaProduct takes nh delta steps per token, so the transition becomes a product of nh reflections. Per slide 27, more reflections mean more state-tracking power.
  • Log-linear attention keeps about log T states covering spans of different sizes, so memory grows slowly with length. It sits between a fixed state (linear) and a state that grows like T (softmax).

The slide is marked "briefly". Know what problem each addresses rather than how it works.

§9Limits: recall and copying

A fixed-size state has to choose what to keep before it knows what will be asked. That costs recall and copying, and the cost can be measured.

Slide 31 / 41
slide 31 · associative recall

On the slide

The Zoology study compared 17 models and found that 82% of the perplexity gap between attention and efficient alternatives comes from tokens that need recalling something seen earlier. On a recall task, a 70M attention model beats a 1.4B gated-convolution model.

What associative recall means

In "Hakuna Matata means no worries ... Hakuna Matata it means no", the next word is "worries" because the text already paired "no" with "worries". To predict it, the model has to find the earlier occurrence of "no" and copy what followed. Attention does this directly with a query that matches the earlier key. A recurrent model can only answer if, when it read "no worries" the first time, it happened to store that pair well enough.

Multi-query AR (MQAR) makes the test harder. Many key–value pairs appear first, then many queries, so the model has to hold all the pairs at once.

Slide 32 / 41
slide 32 · recall vs state size

On the slide

Plotting recall accuracy against state size puts every architecture on one trend. More state gives better recall. Based mixes linear attention with a small sliding window to sit on the best part of that curve.

Why state size bounds recall, with slide 10's example

The 2 × 2 memory from slide 10 stored two pairs perfectly because the keys (1, 0) and (0, 1) were orthogonal. Two-dimensional keys allow at most two orthogonal directions. Add a third pair with key (1, 1)/√2 and value (4, 4), and querying (1, 0) now returns (3, 5) + (4, 4) × (1/√2) ≈ (5.83, 7.83) instead of (3, 5). The new pair has leaked into the old one. In general a dv × dk memory holds about dk pairs cleanly, and past that, reads get noisier. That is the theorem on the slide in miniature. To recall N pairs, the state has to grow with N.

Full attention escapes this only because its "state", the KV cache, grows with the sequence. That is why it sits in the top-right corner of the plot.

Slide 33 / 41
slide 33 · copying

On the slide

Copying a long string, or looking up a number in a long phone book given in context, is easy for Transformers and hard for fixed-state models. The gap grows with the length of what has to be copied.

Why copying is the extreme case

To copy a string of L random characters, the model has to hold all L of them, because nothing about the string can be compressed. Once L exceeds what the state can hold, accuracy has to drop. That is what plot (b) shows for Mamba and the LSTM. A Transformer keeps every character in its KV cache and, with a position-matching attention pattern, can read them back in order however long the string is.

The phone-book task in plot (c) is a realistic version of MQAR. Pythia stays accurate as the book grows, while Mamba of every size falls toward zero by 200 entries. Making Mamba bigger doesn't help, because the problem is the state size per layer, not the parameter count.

§10Hybrids in production

The practical answer to slides 31–33 is to keep a few attention layers for exact recall and make the rest recurrent. The question becomes how few attention layers you can get away with.

Slide 34 / 41
slide 34 · hybrid stacks

On the slide

Three hybrid layouts. Griffin uses 2 recurrent layers per local-attention layer, Qwen3-Next 3 Gated DeltaNet layers per attention layer and MiniMax-01 7 lightning-attention layers per softmax layer.

What the ratio buys

Only attention layers keep a KV cache. Using slide 3's numbers, a 32-layer model with full attention everywhere needs 16 GiB of cache at 32K tokens. At 3:1, only 8 of the 32 layers are attention, so the cache is 4 GiB, plus a small fixed recurrent state. At 7:1 it would be 2 GiB. Each attention layer that remains can still look back exactly, so a recall question like slide 31's can be answered by those layers while the recurrent layers handle everything else cheaply.

The design knobs listed on the slide are the open questions. They are the ratio, where the attention layers sit in the stack, which recurrent layer to use, and whether attention is global or a sliding window.

Slide 35 / 41
slide 35 · MiniMax-01

On the slide

MiniMax-01 has 80 layers, with softmax attention in every 8th and lightning attention in the rest, and an MoE feed-forward with 32 experts. It has 456B parameters in total, 45.9B active per token, and was trained with 1M-token contexts.

Putting it together

Lightning attention is linear attention computed in the chunkwise way of slide 9 (parallel inside a block, recurrent between blocks). With one softmax layer in 8, only 10 of the 80 layers keep a KV cache, which is what makes 1M-token training contexts affordable. The MoE part is the same idea from Assignment 2, where only a few experts run for each token, which is why "active" parameters are a tenth of the total.

Slide 36 / 41
slide 36 · Qwen3-Next and Qwen3.5

On the slide

Qwen3-Next and Qwen3.5 both repeat a unit of three Gated DeltaNet layers and one gated attention layer, with MoE feed-forwards. Qwen3-Next reports over 10× the throughput of the dense Qwen3-32B beyond 32K context.

Details worth noticing in the figure

The Gated DeltaNet block normalises q and k with an L2 norm. That keeps ‖k‖ = 1, which slide 27's eigenvalue argument assumes and which stops the I − βkk⊤ factor from blowing up. It also has a short convolution before the recurrence, playing the same role as RWKV's token shift and Griffin's Conv1D. The attention layer applies RoPE (Lecture 4) to only part of each head, and only these attention layers keep a KV cache. In Qwen3.5 that is 15 of 60 layers.

Slide 37 / 41
slide 37 · Kimi Linear vs MiniMax-M2

On the slide

Two labs reached opposite conclusions in the same month. Kimi Linear (3 KDA layers per MLA layer) reports beating full attention with 75% less KV cache. MiniMax, which shipped the hybrid MiniMax-01, went back to full attention for M2.

Why they can both be right

The 75% saving is just the ratio again, since only 1 layer in 4 keeps a cache. MiniMax's reasons are about what is hard to see. Multi-hop reasoning failures only appeared on expensive evaluations, not on standard benchmarks or perplexity, which matches the recall limit of slides 31–33. The rest are engineering issues. Serving systems have years of optimisation for attention, such as prefix caching and speculative decoding (Lecture 11), and these are harder to apply when part of the model's memory is a recurrent state that can't be cut and reused at an arbitrary token. Lecture 12's point applies here. A claim that one model is "as good" depends on which evaluation you trust.

Slide 38 / 41
slide 38 · the 2026 landscape

On the slide

Open-weight models released in early 2026 fall into five groups. Linear-RNN hybrids, purely recurrent models, sliding-window hybrids, full or sparse attention, and SSM hybrids. There is no consensus.

The common thread

Every group is answering slide 3's problem in some way. Even the "full attention" group shrinks the KV cache by other means, with GQA and MLA (Lecture 5) or sparse attention. Sliding-window hybrids cap the cache of most layers at the window size. The groups differ in how much exact look-back they are willing to give up. The slide's three deciding factors are long-context quality, how well serving software supports the design, and how expensive long generations are.

§11Summary and what's next

The deck closes with a five-point summary, a preview of state space models, and reading.

Slide 39 / 41
slide 39 · summary

On the slide

Five points. Decode cost brought RNNs back, linearity in the state makes them trainable in parallel, the models differ in their update rule, a fixed state limits recall, and so production models are hybrids, though not everyone agrees.

Point 3 as one line per model

  • Additive. S += vk⊤ (linear attention).
  • Fixed decay. S ← γS + vk⊤ (RetNet).
  • Data-dependent decay. S ← S diag(αt) + vk⊤ (GLA, RWKV-6, Mamba-2, mLSTM, RG-LRU).
  • Delta rule. S ← S + β(v − Sk)k⊤ (DeltaNet, Gated DeltaNet, RWKV-7).
  • Learned optimiser. W ← W − η∇ℓ (TTT).

If you can place a new model on this ladder and say what it gains over the step below, you have the main idea of the lecture.

Slide 41 / 41
slide 41 · resources

On the slide

Blogs, code repositories and the core papers in lecture order.

Where to start

Songlin Yang's three-part DeltaNet blog covers slides 7–10 and 24–27 in more depth, including the chunkwise algorithm and the WY representation. The flash-linear-attention repository has working implementations of most models in slide 26's table, which helps for Assignment 3.

Zoom out. A Transformer's cost per generated token grows with the context because it keeps every key and value. A recurrent layer keeps a fixed-size state instead, and the modern versions make that state a dv × dk matrix that stores key → value pairs. Two ideas make them practical. Gates that depend only on the current input make the recurrence linear in the state, so it can be trained with a parallel scan or chunk by chunk, and decoded in O(1) per token. The update rule then decides quality. Linear attention only adds, RetNet adds a fixed decay, GLA, Mamba-2 and RWKV-6 let each token choose the decay, and DeltaNet and RWKV-7 overwrite the value for one key, which is a gradient step and leads to TTT. A fixed state still can't recall or copy as much as a growing KV cache, so the models in production keep one attention layer in every four to eight. For an exam, be able to compute a small linear recurrence by hand and with the scan operator, explain the KV-cache arithmetic, write Mt for each model in slide 26's table, and run one delta-rule update on a 2 × 2 memory.

§2Q1 · GQA, DeltaNet, SmoothQuant

Q1 3 marks GQA DeltaNet SmoothQuant

How to approach it

Every subquestion has more than one correct option, and each option is judged on its own. Test each one against the definition, not against the other options. Writing one line of algebra is the fastest check for the DeltaNet part.

Q1.1 · GQA with 16 query heads and 4 KV heads — answer: (b), (c)

OptionVerdictWhy
(a) heads in a group give identical attentionFalseThey share K and V, but each head has its own query projection, so softmax(qhK⊤) differs per head.
(b) group size 16 = MQATrue16 query heads per KV head means one KV head for all of them, which is multi-query attention.
(c) group size 4 uses ¼ of MHA's cacheTrueThe cache stores K and V per KV head: 4 heads instead of 16, everything else equal.
(d) doubling length leaves cache unchangedFalseThe cache grows linearly with sequence length for both MHA and GQA. GQA only changes the constant.
(e) fewer distinct query headsFalseGQA groups the K/V heads. There are still 16 query heads.

Q1.2 · The delta rule — answer: (a), (c), (d), (e)

Multiply the update by any key w:

S′w = Sw + β (v − Sk)(k⊤w)
  • (a) True. At w = k, k⊤k = 1, so S′k = Sk + β(v − Sk). With β = 1 this is exactly v.
  • (b) False. At w = u, k⊤u = 0, so S′u = Su. The readout at u does not move, so it is v only by coincidence.
  • (c) True. If Sk = v the error term v − Sk is zero and the whole update is zero.
  • (d) True. If k⊤w ≠ 0 and v ≠ Sk, the readout at w changes by β(v − Sk)(k⊤w). This is the interference between non-orthogonal keys.
  • (e) True. With β = ½, S′k = ½ Sk + ½ v, the midpoint.

Q1.3 · SmoothQuant — answer: (c), (d), (e)

  • (a) False. Equality X′W′ = XW holds before quantization. Rounding X′ and W′ adds error, so the product is only approximately XW.
  • (b) False. Splitting outlier channels into a separate FP16 matmul is LLM.int8(). SmoothQuant keeps one INT8 matmul and moves scale between the two operands.
  • (c) True. XS−1SW = XW.
  • (d) True. The bit width is the same, but the ranges being quantized have changed, so the rounding error changes. Reducing that error is the whole point.
  • (e) True. Column j of X is divided by Sjj > 1, and row j of W is multiplied by it.

§3Q2 · Dense FFN vs Mixture-of-Experts

Q2 5 marks FFN MoE

Worked answer

1 · Parameter counts (d = 2048, no biases)

One FFN has two matrices, d × 4d and 4d × d, so 8d² parameters.

TotalActive per token
Dense FFN8d² = 8 × 2048² = 33,554,432 (≈ 33.6M)all of it: 33,554,432
MoE, 8 experts, top-28 × 8d² = 268,435,456 (≈ 268.4M)2 × 8d² = 67,108,864 (≈ 67.1M)

The router adds a d × 8 matrix, 16,384 parameters. Every token uses it, so including it gives 268,451,840 total and 67,125,248 active. State whichever convention you use. The MoE stores 8× the parameters of the dense FFN but does only 2× its compute per token.

2 · What stops every expert from running

A learned router (gate) scores the experts for each token, and only the top-k experts are evaluated. The other six are never called for that token, so their parameters cost memory but no compute.

  1. Router logits z = Wrx (one score per expert), then p = softmax(z).
  2. Keep the two largest, topk(p, 2), and renormalise them so the two gates sum to 1.
  3. Output y = g1Ei(x) + g2Ej(x). Multiplying by the gate probability is what lets the main loss send a gradient to the router.
  4. An auxiliary load-balancing loss E · Σe fePe (Switch Transformer) keeps the router from collapsing onto one or two experts. The A2 code also used the ST-MoE router z-loss to keep logits small.

PyTorch modules, as in A2:

  • self.router = nn.Linear(d, E, bias=False) gives one score per expert per token.
  • self.experts = nn.ModuleList([FFN(d) for _ in range(E)]), where each expert is nn.Linear(d, 4d) → nn.GELU() → nn.Linear(4d, d).
  • softmax and torch.topk pick the experts and their gates.
  • For dispatch, loop over experts, find the tokens routed to each with (topi == e).nonzero(), run the expert on just those rows, and add the gated output back with out.index_add_(0, tok, y).

§4Q3 · Outliers and SmoothQuant

Q3 4 marks Quantization

Worked answer

1 · The outlier problem. INT8 quantization maps a tensor onto 256 levels using a scale set by its largest absolute value. In LLMs (from about 6.7B parameters up) a few activation channels are systematically up to ~100× larger than the rest. With one scale per tensor, the outliers set the step size, and the ordinary values, which carry most of the signal, fall into a handful of levels or round to zero. Weights are well behaved and quantize easily. Activations are the hard part, and per-channel activation scales do not fit an efficient INT8 GEMM.

2 · SmoothQuant. It is a training-free, offline transform that makes W8A8 (INT8 weights and activations) work. For each input channel j it picks a smoothing factor

sj = max|Xj|α / max|Wj|1−α,  α ≈ 0.5

and rewrites Y = XW = (X diag(s)−1)(diag(s) W). Some of the activation range moves into the weights, so both sides end up with moderate ranges and both quantize well. The division can be folded into the preceding LayerNorm or linear layer, so it costs nothing at inference.

3 · Which way. Activations are scaled down (divided by sj) and the matching weight rows are scaled up (multiplied by sj). The output is unchanged because the diagonal scaling and its inverse cancel: X S−1 S W = XW. This is exact before quantization.

§5Q4 · Diagnosing bad behaviour

Q4 5 marks Evaluation

Worked answer

1 · 95% accuracy, but everything is "not spam"

Conclusion. The data is imbalanced: about 95% of the documents are not spam. A model that always predicts the majority class gets 95% accuracy, and that is what it learned. The high accuracy hides that spam recall is zero. Validation and test had the same imbalance, so they could not catch it. Deployment just made it visible.

Simplest change. Balance training, by oversampling spam, undersampling non-spam, or using class-weighted cross-entropy. Select models on spam precision, recall, F1 or AUC instead of accuracy. (If the deployment spam rate differs from the training rate, that is distribution shift too, and the fix is to train and validate on data drawn like deployment data.)

2 · Near-perfect reward, terrible BLEU

Conclusion. The model is reward hacking. d(Ŝ, S) = |Ŝ ∩ S| / |Ŝ| is a bag-of-words precision. It never asks whether the output covers the target, and it ignores word order. The policy can score 1.0 by emitting one or two safe words that are almost always in the target (say "the") and then ⟨eos⟩, or by emitting target words in any order. BLEU punishes exactly this: its n-gram matches need order, and its brevity penalty punishes short outputs.

Simplest change. Add recall to the reward, for example BOW F1, or divide by max(|Ŝ|, |S|) rather than |Ŝ|, so short outputs stop scoring well. Better still, reward n-gram overlap with a brevity penalty (BLEU itself). A KL penalty to the pretrained model also keeps the policy from drifting into degenerate text.

§6Q5 · Dense vs diagonal state matrices

Q5 8 marks SSMs Mamba SLiCE paper

How to approach it

Part 1 asks for a proof, so a counterexample is the cleanest answer. Say which numbers are allowed (real or complex) before you start, because the answer depends on it. Part 2 wants three things from the paper: diagonal transitions commute, Theorem 4.1, and the layer counts in Fig. 1a.

Worked answer

1 · They are not equivalent

Assumptions. Mamba's A is real and diagonal (in practice negative, so Ā = exp(ΔA) has entries in (0, 1)). Hidden size dh is fixed. To disprove the claim, it is enough to find one dense model, even with constant Δ, that no real diagonal model of the same size can match.

Counterexample (rotation). Take dh = 2, A = [[0, −ω], [ω, 0]], B = e1, C = e1⊤. Then Ā = exp(ΔA) is a rotation by θ = ωΔ, and the impulse response is yt = CĀtB = cos(θt). A size-2 real diagonal model has impulse response c1λ1t + c2λ2t with real λi. Sequences λt with distinct bases are linearly independent, and cos(θt) = ½(eiθt + e−iθt) has non-real bases e±iθ (for θ not a multiple of π). So no choice of real λ, c reproduces it. A real diagonal model cannot rotate. It can only decay each coordinate (or flip its sign if λ < 0).

Second counterexample (not diagonalisable). A = [[a, 1], [0, a]] gives Āt an entry tΔ eaΔt. A sum of pure exponentials cannot produce t·λt, even with complex numbers.

When it does hold. If complex diagonal entries are allowed (as in S4D) and A is diagonalisable, A = VΛV−1, then h̃ = V−1h gives an equivalent diagonal model with B̃ = V−1B, C̃ = CV. Because every exp(ΔtA) is a function of the same A, one V works for all steps even with input-dependent Δt. Equivalence fails once the transition's directions depend on the input, as in a linear CDE with a different Ai per input channel. Those matrices do not commute, so no single basis diagonalises them all. That is part 2.

2 · Why Mamba is less expressive than BD-SLiCE

  • In the paper's framework, a model's transition over a step is exp(Σi ΔωiAi). Mamba is the diagonal case, a D-SLiCE (Sec. 4.2). Diagonal SLiCEs are not maximally expressive (Cirone et al. [22, Thm 4.3]).
  • The reason is that diagonal matrices commute. The product of the transitions over a sequence is the same in any order, so the state cannot record the order in which transformations were applied. That is exactly what state tracking needs.
  • BD-SLiCE uses Ai = BlockDiag(Bi1, …, Bik) with dense, input-dependent blocks (Sec. 4.3). Blocks do not commute, so order is kept. Theorem 4.1: if the largest block size grows with dh, BD-SLiCEs have maximal probabilistic expressivity, the same as dense LNCDEs. Block-diagonal matrices stay block-diagonal under multiplication, so the parallel scan costs O(dh Σ bj2) per composition rather than O(dh3) (Sec. 4.6).
  • A5 (Fig. 1a). The task composes even permutations of five elements. This group is non-abelian, so the answer depends on the order. Diagonal models (Mamba, mLSTM, D-SLiCE) need more stacked layers as the sequence gets longer (several layers by length 20), because each layer plus its non-linearity can only cover a bounded amount of non-commutative composition. BD-SLiCE, like the DPLR, sparse, WH and dense SLiCEs, needs one layer at every length from 3 to 20. In Fig. 1b, BD-SLiCE keeps high accuracy at 8× the training length, while Mamba does not reach high accuracy even at training lengths.

§7Q6 · Debugging SLiCE code

Q6 10 marks parallel scan DeltaNet SLiCE paper

How to approach it

Trust the docstrings. They state the maths, so check each line against the docstring and the section it cites. For each bug, give the line number, the reason with a paper reference, and the corrected line.

6.1 · BlockDiagSLiCE

Line 19 has two bugs.

  1. It averages the input over time. dw.mean(dim=1) collapses the sequence, so every step uses the same transition M. A SLiCE's transition at step t is built from that step's increment, exp(Σi ΔωtiAi) (Eq. 2, Eq. 13). With one shared M the layer becomes time-invariant, hT = MTh0. The inputs only affect it through their average, so word order is lost. The "pre-compute once" comment is the trap. You can precompute every step's matrix, but not a single shared one.
  2. It drops the identity. The docstring's first-order flow is I + Σi ΔωiAi (Eq. 13). Without I, each step replaces h by the increment (Σ ΔωiAi)h instead of adding the increment to h, so the state no longer follows the CDE.
19    M = torch.einsum('btc,cnij->btnij', dw, self.A) \
          + torch.eye(self.b, device=x.device)               # (B, T, nb, b, b)
23        h = torch.einsum('bnij,bnj->bni', M[:, t], h)          # step t's own transition

6.2 · blockdiag_prefix_flows

Line 3: the composition is in the wrong order. The docstring says ht+1 = P[t] h0, so P[t] = Mt ⋯ M1M0. Later steps multiply on the left. The scan at line 14 calls combine(P[:-d], P[d:]) with the earlier prefix first, so earlier @ later builds M0M1⋯Mt, the reverse.

3     return later @ earlier

Line 11: it throws away the block structure. torch.block_diag turns each step into a dense dh × dh matrix, so every composition costs O(dh3). Sec. 4.6 says block-diagonal matrices are closed under multiplication, so the scan should compose the blocks directly at O(dh b2). That is the point of BD-SLiCE. @ on (…, nb, b, b) tensors already multiplies block by block.

11    P = M.clone()                                   # (T, nb, b, b), stays block-diagonal

Why the test passed. If every block is diagonal, every Mt is diagonal, and diagonal matrices commute, so earlier @ later = later @ earlier. The order bug has no effect on exactly the inputs that were tested. It is the same fact that limits Mamba in Q5: a test made only of commuting transitions cannot find an ordering mistake. Test with random dense blocks.

6.3 · DeltaNetPM1

The transition I − βtktkt⊤ has eigenvalue 1 − βt‖kt‖² along kt and 1 in every other direction. For it to lie in [−1, 1] as the docstring requires, two things must hold.

  1. Line 17: keys are not normalised. With raw keys, ‖k‖² can be anything. For example ‖k‖ = 3 and β = 1 give eigenvalue −8, and the state blows up. DeltaNet L2-normalises keys (and usually queries) so that ‖k‖ = 1. 
    17    q, k, v = F.normalize(self.q(x), dim=-1), F.normalize(self.k(x), dim=-1), self.v(x)
  2. Line 18: β is in [0, 1], so the eigenvalue is in [0, 1]. That is plain DeltaNet. The [−1, 1] variant in Table 2 (from Grazzi et al. [38]) allows negative eigenvalues by letting β range over [0, 2], so 1 − β ∈ [−1, 1]. Negative eigenvalues are what let it solve parity and modular arithmetic (97.7 vs 57.8 on parity in Table 2). 
    18    beta = 2 * torch.sigmoid(self.beta(x))          # (B, T, 1), in [0, 2]

The rest is correct. Line 23 computes Sk. Lines 24–25 compute S − β(Sk)k⊤ + βvk⊤ = S(I − βkk⊤) + βvk⊤. Line 26 reads out Sq.

§8Q7 · Speculative sampling

Q7 15 marks Speculative decoding

Worked answer

1 · One iteration

  1. Draft. Run q autoregressively for γ steps, sampling x1, …, xγ and keeping qi(xi).
  2. Score. Run the target once on the prefix plus all γ drafts. This gives p1, …, pγ+1: one distribution per draft position and one extra after the last.
  3. Verify in order, for i = 1 … γ: draw r ~ U(0, 1) and accept xi if r < min(1, pi(xi) / qi(xi)).
  4. On the first rejection at position i, discard xi, …, xγ, sample a replacement from the residual p′(x) = max(0, pi(x) − qi(x)) / Σy max(0, pi(y) − qi(y)), and end the iteration.
  5. If all γ are accepted, sample one more token from pγ+1, which the target pass already computed. Each iteration emits between 1 and γ + 1 tokens.

2 · The output is distributed exactly as p

Let α = Σx min(p(x), q(x)) be the overall acceptance probability. A token x comes out either by being drafted and accepted or by being sampled after a rejection:

P(x) = q(x)·min(1, p(x)/q(x)) + (1 − α)·max(0, p(x) − q(x)) / (1 − α)

The first term is min(q(x), p(x)). For the second, the normaliser of the residual is Σ max(0, p − q) = Σ (p − min(p, q)) = 1 − α, the same as the rejection probability, so they cancel. Then P(x) = min(p(x), q(x)) + max(0, p(x) − q(x)) = p(x), for any q. (If α = 1, then p = q, nothing is rejected, and P = q = p.)

3 · Acceptance rate

α = Σx q(x) min(1, p(x)/q(x)) = Σx min(q(x), p(x)). Using min(a, b) = (a + b − |a − b|)/2 and Σp = Σq = 1: α = ½(1 + 1 − Σ|p − q|) = 1 − TV(p, q).

For p = (0.5, 0.3, 0.2) and q = (0.6, 0.1, 0.3): α = min(0.5, 0.6) + min(0.3, 0.1) + min(0.2, 0.3) = 0.5 + 0.1 + 0.2 = 0.8. Check: TV = ½(0.1 + 0.2 + 0.1) = 0.2.

After a rejection: max(0, p − q) = (0, 0.2, 0), which normalises to (0, 1, 0). A rejection always produces b, the only token the draft under-proposes.

4 · Expected tokens and speed-up

Positions are accepted until the first rejection, with each accepted with probability α. The iteration always produces one token at the end (the correction or the bonus), so

E[tokens] = 1 + α + α² + … + αγ = (1 − αγ+1) / (1 − α)

An iteration costs γ draft steps plus one target pass, γc + 1 in target-pass units. Plain decoding makes 1 token per target pass, so the speed-up is (1 − αγ+1) / ((1 − α)(γc + 1)).

γE[tokens]Cost γc + 1Speed-up
2(1 − 0.8³)/0.2 = 2.4401.22.03×
4(1 − 0.8⁵)/0.2 = 3.3621.42.40×
6(1 − 0.8⁷)/0.2 = 3.9511.62.47×
8(1 − 0.8⁹)/0.2 = 4.3291.82.41×

Best: γ = 6. A larger γ eventually hurts because the gain saturates while the cost does not. Draft i only counts if all earlier ones were accepted, which happens with probability αi. Expected tokens approach 1/(1 − α) = 5, but each extra draft still costs c, and long drafts are mostly thrown away.

5 · Two follow-ups

Greedy decoding. Both distributions are one-hot on their argmax. The ratio p(x)/q(x) is 1 if the draft's token is the target's argmax and 0 otherwise. So the rule becomes "accept if the draft token equals the target's argmax". On a mismatch, the residual is one-hot on the target's argmax. The output is exactly the target model's greedy output, just faster.

Why not "accept if p(x) ≥ q(x), else sample from p". Then P(x) = q(x)·𝟙[p(x) ≥ q(x)] + P(reject)·p(x), which is not p. With the numbers above, only b is ever accepted, P(reject) = 0.6 + 0.3 = 0.9, and the output is (0.45, 0.37, 0.18) instead of (0.5, 0.3, 0.2). Accepted tokens are already counted once, so the fallback must sample only the missing mass max(0, p − q). Sampling all of p double-counts tokens where q already supplied some probability. Accepting with probability p/q when p < q is what removes the excess.

§9Section B · Part 1: Mamba and DeltaNet

B1 4 × 5 marks A3 Mamba

1 · How Mamba sees order when its transitions commute

Commuting transitions only lose the order of the transitions among themselves. The inputs still enter at different times. Unrolling the recurrence:

hT = Σt ( Πs=t+1T Ās ) B̄t xt

Each input is scaled by the decay of every step after it, so its weight depends on how long ago it arrived. Recency works as an implicit position signal. Selectivity strengthens this: Δt, Bt and Ct depend on the input, so later tokens decide how much of earlier ones survives (a large Δ resets, a small Δ keeps). The short causal Conv1d before the SSM also sees the exact order of the last few tokens. And the recurrence is causal by construction, so the model never needs positions to tell past from future the way attention does.

2 · Why an evolving-state cipher is hard for Mamba, and what DeltaNet adds

The cipher's chained shift adds to each symbol a running quantity computed from all earlier symbols, modulo 63. That is state tracking. Mamba's transition is exp(ΔtA) with real negative diagonal A, so each coordinate can only shrink by a factor in (0, 1). It cannot rotate or flip sign, so it cannot count modulo n (it cannot even do parity), and diagonal transitions cannot compose non-commuting updates in one layer (Q5). DeltaNet's transition I − βtktkt⊤ is a generalised Householder matrix whose direction depends on the input. It is not diagonal, consecutive steps do not commute, and with β ∈ [0, 2] it can reflect, which gives eigenvalue −1. Its delta rule also overwrites the value stored at a key, so it can update a variable instead of piling up history. In our assignment the unchain preprocessing undid the chained shift before training, which is why all four models reached above 99.9%.

3 · Why the hybrid looks the way it does

Design: embed → [Mamba → DeltaNet + MLP] × 3 → RMSNorm → Linear(27), about 3.75M parameters, matched to the other models.

  • Mamba as a local feature extractor. Its short convolution and selective Δ summarise the last few cipher symbols.
  • DeltaNet as an associative memory. It stores key → value pairs and overwrites old values, which fits a mapping from cipher patterns to plaintext characters. It works best when keys are informative, so Mamba comes first and DeltaNet's keys are built from contextual features rather than raw symbol embeddings.
  • Interleaved, not stacked in halves. After each memory read, the next Mamba layer mixes the result across neighbouring positions before the next lookup (as in Jamba, Samba and the Gated DeltaNet hybrids).
  • Hypotheses. H1: the hybrid is at least as good as the better pure model. H2: after preprocessing every model should be near-perfect, so any gap would be small. H2 held (0.9991–0.9995 test accuracy). The hybrid had the lowest validation loss, but the gaps were within noise.

4 · How DeltaNet extends linear attention

Linear attention drops the softmax and keeps a running sum St = St−1 + vtkt⊤, reading out ot = Stqt. The state has fixed size and decoding costs O(1) per token. The limitation is that the memory is purely additive. It never forgets or overwrites, so once more than dk keys are stored they cannot all be orthogonal, and retrievals interfere. A key written twice returns the sum of both values.

DeltaNet uses the delta rule: first read what the memory predicts for the key, then write only the error.

St = St−1 + βt(vt − St−1kt)kt⊤ = St−1(I − βtktkt⊤) + βtvtkt⊤

This is one step of online gradient descent on ½‖Skt − vt‖², with β as the learning rate. The old value at kt is replaced instead of added to, which fixes the capacity and interference problem. The transition is identity minus rank one (DPLR), which still trains in parallel with the chunkwise WY algorithm.

§10Section B · Part 2: GNNs

B2 5 + 5 + 10 marks A3 · Part B

1 · The GCN layer

H(l+1) = σ( D̃−½ Ã D̃−½ H(l) W(l) ),   Ã = A + I,   D̃ii = Σj Ãij
  • H(l) is the node features at layer l (n × d), and W(l) is a learned weight matrix shared by all nodes.
  • Ã is the adjacency matrix with self-loops, and D̃ its degree matrix. σ is a non-linearity (ReLU).
  • Per node: hi′ = σ(Σj∈N(i)∪{i} W hj / √(d̃id̃j)).

Self-loops let a node keep its own features. Without them, AH replaces each node by its neighbours alone. Normalisation is needed because AH sums neighbours, so high-degree nodes get large vectors and repeated layers explode or vanish. The symmetric D̃−½ÃD̃−½ averages instead, weights each edge by 1/√(d̃id̃j), and keeps the propagation matrix's eigenvalues in [−1, 1].

2 · UPFD GossipCop

  • A graph is one news article and its Twitter propagation tree. Node 0 is the article, and every other node is a user who shared it.
  • Edges follow propagation: u → v means the story reached v through u (a retweet cascade).
  • Features: profile (10, account metadata), spacy (300, averaged word vectors of the user's tweets, or of the article for node 0), bert (768, BERT embedding of the same text), content (310 = spacy 300 + profile 10).
  • Task: binary graph classification, deciding whether the article is fake or real. There are 5,464 graphs, with the dataset's fixed 20/10/70 train/val/test split.

3 · GCN vs GraphSAGE vs GAT

(a) How each node combines its neighbours

ModelUpdate for node i
GCNhi′ = σ( Σj∈N(i)∪{i} W hj / √(d̃id̃j) )
GraphSAGE (mean)hi′ = σ( W1hi + W2 · meanj∈N(i) hj ) (equivalently W[hi ‖ mean])

(b) How they weight neighbours

GCN uses fixed weights that come only from the graph structure (1/√(d̃id̃j)), and treats self the same as a neighbour. GraphSAGE weights all neighbours equally (a plain mean) but gives the node itself a separate weight matrix, so it is not drowned out by many neighbours. GAT learns the weights: each edge gets an attention score computed from the two nodes' features, so different neighbours, and different heads, can matter differently.

(c) From node embeddings to one graph vector

Apply a permutation-invariant readout (global pooling) over all nodes in the graph, then a classifier such as Linear(d, 2). Two readouts: global mean pooling (what A3 used, a scatter-sum by graph id divided by the node count) and global max pooling. Sum pooling, attention pooling, or using the root (article) node's embedding also work.

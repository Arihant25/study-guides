The big idea

What is a detection problem?

You get some noisy measurements and must answer a yes/no question:

  • A radar asks whether there's an aircraft or just noise.
  • A Wi-Fi receiver asks whether a 0 or a 1 was sent.
  • An ECG monitor asks whether a heartbeat is normal.

The two possible answers are called hypotheses: H₀ = "nothing there" and H₁ = "signal there".

Every detector in this course works the same way: compute one number from the data, compare it to a threshold, and say yes if it's bigger. The topics differ only in which number and where the threshold comes from.

The course goes from easy to hard:

  1. Signal fully known → matched filter
  2. Signal is random → estimate it, then match
  3. Signal has unknown parts → plug in a best guess (GLRT)
  4. Data arrives one sample at a time → stop as soon as you're sure (SPRT)

Two ways to be wrong

What can go wrong when you say yes or no?

Truth: nothing thereTruth: signal there
You say "no"✓ correct✗ Miss (PM)
You say "yes"✗ False alarm (PFA)✓ Detection (PD)
  • \(P_D + P_M = 1\): catching more means missing less.
  • You can't make both errors small for free. Always saying "yes" means zero misses, but every noise blip is a false alarm.
  • You have to choose a trade-off. Bayes and Neyman–Pearson (next two sections) are two ways of choosing it.
Other names for the same thing
  • False alarm = Type I error = α (also called the "size")
  • Miss = Type II error = β; detection = "power" = 1 − β

The one tool: the likelihood ratio

How do you turn data into a yes/no?

Ask: how much more likely is this data if the signal is there than if it isn't?

Likelihood ratio test
\[L(\mathbf x)=\frac{\text{chance of this data if signal present}}{\text{chance of this data if no signal}}\ \ >\ \ \gamma\ \Rightarrow\ \text{say yes}\]

γ (gamma) is the threshold.

In practice the ratio simplifies to something easy. For Gaussian noise it almost always becomes an average, a sum of squares, or a correlation. Use this recipe every time:

  1. Write the ratio of the two probability formulas.
  2. Take the log, so products become sums and exponentials disappear.
  3. Throw away everything that doesn't involve the data. What's left is your test number \(T(\mathbf x)\).
  4. Work out how \(T\) behaves with and without the signal, and read off PFA and PD.
Trap
  • Taking logs, adding constants and multiplying by positive numbers are all safe, because the threshold absorbs them.
  • Dividing by a number whose sign you don't know (like an unknown amplitude A) flips the ">" and breaks the test.

Sufficient statistic is a fancy name for "the one number \(T\) that holds all the useful information". For a DC level it's the average. For a change in power it's the sum of squares. Once you have it you can forget the raw data.

Bayes: when you know the odds

Where does the threshold come from if you know how often each case happens?

In communications you know 0s and 1s are sent equally often, and you know what each mistake costs. Bayes uses that knowledge to minimise the average cost.

Bayes threshold
\[\gamma=\frac{P(\text{no signal})\times\text{cost of a false alarm}}{P(\text{signal})\times\text{cost of a miss}}\]

If both mistakes cost the same, γ = P(H₀)/P(H₁). This is the MAP detector: pick the more probable answer. If the priors are also equal, γ = 1, and you get the ML detector: pick the answer that best explains the data.

Priors and costs only move the threshold. The test number stays the same.
Intuition
If the signal is usually there (P(H₁) = ¾), the threshold drops and you say "yes" more easily. You accept a few more false alarms to cut misses.

With more than two answers (M hypotheses), pick the one with the lowest expected cost. With equal costs that means picking the most probable one.

Neyman–Pearson: when you don't know the odds

What if nobody can tell you how likely an enemy aircraft is?

In radar there's no sensible prior, and a miss is far worse than a false alarm. So the rule changes: decide how many false alarms you can live with, then catch as many real signals as possible.

NP rule
\[\text{Fix } P_{FA}=\alpha\ (\text{e.g. } 10^{-6}),\ \text{then maximise } P_D.\]

The answer is still the likelihood ratio test. The threshold is now set so that PFA = α, which uses only the noise-only case.

Bayes and Neyman–Pearson give the same test. They just pick the threshold differently.

Discrete data: flip a coin at the boundary

With counts (like binomial data) PFA jumps in steps, so you may not hit α exactly. The fix: when the data lands exactly on the threshold, say "yes" with some probability c.

Example (classwork)

10 coin tosses. Fair coin (p = 0.5) or biased (p = 0.8)? Target α = 0.05. Count the heads, x.

  • Saying yes at x ≥ 9 gives PFA = 0.011: too few false alarms, wasting power.
  • Saying yes at x ≥ 8 gives PFA = 0.055: too many.
  • So: x ≥ 9 → yes, x ≤ 7 → no, x = 8 → yes with probability 0.893. This hits exactly 0.05, with PD ≈ 0.65.

The main example: a constant in noise

Most other topics build on this example.

You get N samples. With no signal they're pure noise (variance σ²). With the signal, each sample has a constant A added.

The test: average the samples, and say yes if the average is big.

Averaging N samples shrinks the noise by a factor of N but keeps A, so more samples means better detection.

How good is it? (the formula you'll use most)
\[P_D=Q\Big(Q^{-1}(P_{FA})-\sqrt{d^2}\Big),\qquad d^2=\frac{N A^2}{\sigma^2}=\text{N}\times\text{SNR}\]

d² is the signal strength after all the processing. Bigger d² means a better detector. Doubling N adds 3 dB.

What is Q?

\(Q(x)\) = the chance that a standard bell curve lands above x. \(Q^{-1}\) goes the other way. You only need a few values:

Design example from the slides

We want PD = 0.99 at PFA = 10⁻⁶, and each sample has SNR = 0.1. How many samples?

√d² = 4.75 + 2.33 = 7.08, so d² ≈ 50. Then N = 50 / 0.1 ≈ 500 samples.

With equal priors (Bayes), the threshold sits halfway at A/2 and the error rate is \(P_e=Q(\tfrac12\sqrt{d^2})\).

The ROC curve

How do you see the whole trade-off at once?

Slide the threshold from very high to very low and plot PD against PFA. That curve is the ROC. Try it:

The dashed line is guessing. A stronger signal bends the curve toward the top-left corner, which is a perfect detector.
  • It always goes from (0,0) to (1,1) and stays above the diagonal.
  • It's concave (bulges up), and its slope at any point equals the threshold used there.
  • To design with it, take PFA from the spec and the PD you need, then read off the d² (signal strength) that gets you there.
Trap
Only compare two detectors at the same false-alarm rate.

The energy detector

What if the signal doesn't shift the average but makes things noisier?

If the signal shows up only as extra power (variance goes from σ₀² up to σ₁²), the average stays at zero and is useless.

The test: add up the squares of the samples (the total energy), and say yes if it's big.
  • A sum of squared Gaussians follows a chi-squared (χ²) distribution. That's what PFA and PD come from. χ²N has mean N and variance 2N.
  • For N = 2 there's a neat exact answer: \(P_D = P_{FA}^{\ \sigma_0^2/\sigma_1^2}\).
  • For large N, χ² looks like a bell curve, so you can use Q.

The same idea gives the exponential data classwork: add up the samples, and for one sample \(P_D=P_{FA}^{\lambda_1/\lambda_0}\).

Known signal: the matched filter

You know exactly what the signal looks like (e.g. your own radar pulse). How do you find it in noise?

The test: multiply the data by a copy of the signal, sample by sample, and add it up (correlate). If the signal is there, the products line up and the sum gets big.
Matched filter
\[T=\sum_n x[n]\,s[n],\qquad d^2=\frac{\text{signal energy}}{\sigma^2}\]
  • It's called a "matched filter" because you can build it as a filter whose response is the signal flipped in time, sampled at the end.
  • It gives the highest possible SNR of any linear filter.
  • In white noise only the signal's energy matters. A pulse, a chirp and a sine with equal energy are equally easy to detect.

Coloured (correlated) noise

If the noise samples are correlated, or some are noisier than others:

  1. Whiten: apply a filter that turns the noise back into plain white noise.
  2. Then use the normal matched filter on the whitened data.
  • Now the signal's shape matters. Put the signal's energy where the noise is weakest.
  • If some samples are noisier, trust them less (divide each by its noise variance).
  • If two noise samples are almost identical, subtracting them cancels the noise. So correlated noise can make detection easier.

Which signal was sent?

In communications, a signal is always there. The question is which one.

The test: pick the known signal closest to what you received (minimum distance).
  • The error rate depends only on how far apart the signals are, \(P_e=Q\big(\tfrac{\text{distance}}{2\sigma}\big)\).
  • So, for a fixed energy, make the signals as different as possible.

M signals: run M correlators and pick the biggest score (adjusted for energy). Exact error rates are messy, so use the union bound: errors are dominated by the closest pair, roughly \((M-1)\,Q\big(\tfrac{d_{\min}}{2\sigma}\big)\). Good design = maximise the smallest distance.

Random signals

What if the signal itself is random, like speech, fading radio or EEG?

You can't correlate against a waveform you don't know. Both cases now average to zero; the only difference is in the power and correlation pattern.

The test (estimator-correlator): first make your best guess of the signal from the data (a Wiener filter), then correlate the data with that guess.
  • If the signal is white (no pattern), the best guess is just a scaled copy of the data, and the test becomes the energy detector again.
  • If it has a pattern, rotate to the signal's natural directions (eigenvectors) and weight each one by how much signal it carries. Directions with mostly noise get ignored.

When something is unknown

What if you don't know the amplitude, the phase or the noise level?

The likelihood ratio needs those values, so you can't compute it directly. Three situations:

1. One test works for every value (UMP)

If you know A is positive but not its size, "average is big → yes" works for every A > 0, and the threshold doesn't depend on A. That's called uniformly most powerful (UMP).

Trap
If A could be positive or negative, no single test is best. "Big average" catches positive A and "small average" catches negative A. No UMP exists for two-sided problems.

2. Fix 1: average over the unknown (Bayesian)

Assume a probability for each possible A and average it out.

3. Fix 2: plug in your best guess (GLRT)

Estimate the unknown from the data (its maximum-likelihood estimate), then use the normal test as if that guess were true. It's usually easier to carry out than the Bayesian route.

Example: DC level, A unknown, could be ±
  • Both fixes give the same answer: square the average, i.e. say yes if |average| is big. Sign doesn't matter any more.
  • If the noise level is unknown too: divide by the estimated noise power. Then the false-alarm rate no longer depends on the noise level (called CFAR).

Unknown noise variance, one-sided (σ² went up) → the energy detector is UMP. Two-sided → no UMP.

Sequential detection (SPRT)

What if every sample is expensive, like testing a shell that gets destroyed?

Instead of fixing N in advance, look at samples one at a time and stop as soon as you're sure.

Keep a running score (the sum of log-likelihood ratios). Above the top line → say yes. Below the bottom line → say no. In between → take another sample.
Six runs of the same test with α = β = 0.05. Each run stops after a different number of samples.
Where the two lines go (Wald)
\[\text{top}=\ln\frac{1-\beta}{\alpha},\qquad\text{bottom}=\ln\frac{\beta}{1-\alpha}\]

α = false-alarm rate you want, β = miss rate you want. You don't need to know anything else about the data.

  • It always stops eventually.
  • The real error rates come out a bit better than you asked for (the score overshoots the line). The guarantee is that the two real errors together are at most α + β.
  • It needs about half the samples of a fixed-N test on average, or even fewer. That's why it was a wartime secret.
  • Average samples needed ≈ (how far the line is) ÷ (how fast the score drifts). The drift is the KL divergence, a "distance" between the two distributions.
  • It has costs too. A single run can take a long time, you must know both distributions exactly, and the theory assumes independent samples.

Extra ideas from the textbook (Kay)

Short versions of the book results the lectures point to.

  • For a sine wave with unknown phase, correlate with both a cosine and a sine, then square and add. That's the periodogram (one FFT bin). If the frequency is unknown too, look for the tallest FFT peak, which is why nearly all narrowband detectors contain an FFT.
  • Each unknown costs some performance. From best to worst: known signal (matched filter), unknown amplitude, unknown phase, unknown frequency, and knowing only the energy (energy detector).
  • With lots of data, 2 × log of the GLRT follows a chi-squared distribution when there's no signal, so you can always set the threshold.
  • For weak signals, the LMP test uses the slope of the log-likelihood at "no signal". For the DC level that's the average again.
  • In non-Gaussian noise, pass each sample through a nonlinearity and then use a matched filter. With spiky noise (Laplacian, Cauchy) the nonlinearity clips or ignores huge samples, because a big spike is probably noise.
  • On a fading channel the error rate falls only like 1/SNR, compared with exponentially without fading.

Tutorial 1: short answers

Try each one first, then open it. Full workings are on the detailed page.

Q1: One sample, mean 0 or mean 1 (variance 1). Find the NP test and the errors.

Say yes if x > threshold t. Then PFA = Q(t) and PM = 1 − Q(t − 1). The miss-vs-false-alarm plot is a curve bowed toward the origin (an ROC with d² = 1, flipped). Example: PFA = 0.1 gives t = 1.28 and PM ≈ 0.61.

Q2: Show the sample average is sufficient for A.

Expand the Gaussian exponent with the given identity. The part involving A depends on the data only through the average; the rest doesn't involve A. By the factorisation theorem the average is sufficient.

Q3: N = 1, A = 1, σ² = 1. Bayes detector for priors ½/½ and ¼/¾.

Say yes if x > ½ + ln(P(H₀)/P(H₁)).

  • Equal priors: x > 0.5, error 0.31.
  • P(H₁) = ¾: x > −0.60, error 0.22.

When the signal is more likely, the threshold drops, and knowing the prior lowers the error.

Q4: One sample: Laplacian (no signal) vs Gaussian (signal). Decision regions?

The ratio simplifies to (|x| − 1)² < c². Say yes when |x| is close to 1, i.e. two bands around +1 and −1. The Laplacian has more weight near 0 and far out in the tails, so medium values point to the Gaussian.

Q5: Constant A in Cauchy noise. What's the test?

Add up g(x) = ln[(1 + x²)/(1 + (x − 1)²)] over the samples. g rises for x around 1–2, peaks at about x ≈ 1.6, and goes back to 0 for huge x. Cauchy noise has wild spikes, so the test ignores huge samples.
